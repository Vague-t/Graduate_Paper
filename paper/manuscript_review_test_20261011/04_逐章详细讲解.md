| 层次 | 问的是什么 | 例子 | 不能替代什么 |

## 第一章 绪论的详细逻辑

### 1.1 研究起点是错误传播

端到端论辩挖掘同时承担组件定位、组件分类和关系预测。组件不是普通的文本片段，而是“某个精确跨度承担某种原生论辩角色”。关系又引用这些完整组件，因此组件错误会传播到所有相关关系。

原稿图 1-1 以 essay001 展示多个 Premise 指向 Claim T3。该图首先要让读者看到依赖的范围，一个目标组件并不是孤立标签。训练时若改写 T3，多个支持关系都可能改变；推理时若抽错 T3 的范围，多条关系也会失去完整对象匹配。

由此可以重建论文的逻辑起点，但不能把它写成未公开的真实研究历史。根据文稿，作者所押注的是，维护对应与依赖完整性可能比单纯增加样本或增加修改次数更有价值；这一判断仍须消融检验。

### 1.2 两条路线为何属于同一篇论文

第三章和第四章改变的对象不同，却共享同一个问题。

|  | 训练阶段 | 推理阶段 |
| --- | --- | --- |
| 已知材料 | 训练原文与金标图 | 新原文与模型预测图 |
| 允许变化 | 指定组件的文字表达 | 预测组件和关系 |
| 原文是否改变 | 生成一个增强版本 | 原文保持不变 |
| 依赖问题 | 原有标签是否仍能继承 | 旧关系是否因组件身份变化而失效 |
| 核心保护 | 对应映射与可靠因素掩码 | 依赖闭合与完整事务接受 |
| 最终验证 | 未参与增强的测试文本上的抽取质量 | 严格对象计数、误改及成本 |

因此两章的联系不是“都用了大模型”或“都有图”，而是都在处理变化之后的依赖维护。图 1-2 应按这个含义理解，不能读成把测试预测重新当成训练标签。

### 1.3 已有基础和新增设计怎么分

第 1.3.3 节明确以 MCR-BR 为继承基础，原方法已经有多候选排序、类型和跨度调整及关系修改。LoRA、连续提示、JS 散度、MLP 和整数规划也是实现方法，不因被组合到本文就自动成为新的基础理论。

本文新增研究主要落在两个接口。

第一，增强前后的监督接口。哪些关系可能变化，怎样更新全部坐标，哪些因素被确认、屏蔽或保留未知，怎样让成对目标只使用合格对应。

第二，推理修改的决策接口。哪些组件冲突必须一起删除，哪些关系必须重新考虑，固定分数下如何比较完整修改，怎样把约束、编辑、失败和回退纳入一次事务。

这些设计可以有规约价值，却仍需要独立实验才能宣称质量优势。表 1-2 正是在分配这种证明责任。整套训练比较能支持系统条件增量；同数据 NoPair 对照才靠近成对项；Single 与 Sequential 比较才靠近共同接受；SetLocal 与 Single 比较才靠近集合动作。

## 第二章 任务表示与评价的详细讲解

### 2.1 从文字到组件和关系

原稿形式上把文档写为 $D=(x_1,\ldots,x_n)$，$x_i$ 是固定评价分词器的第 $i$ 个 token，组件写为

$$
c=(s,e,t).
$$

$s,e$ 是评价 token 的起止位置，采用从 1 开始的闭区间；$t$ 是组件原生类型。模型使用的子词 token 可能与评价 token 不同。实现还保存原文字符坐标。

二元关系写为

$$
r=(c_i,c_j,\ell),\qquad G=(C,R).
$$

$C$ 是组件集合，$R$ 是关系集合，$\ell$ 是关系标签；方向从提供理由或攻击的一方指向目标。一个关系不是两个显示 ID 的连接，而是完整端点身份与标签的组合。

**教学例子。** 某组件字符范围为 $[10,20)$，类型为 Premise。把显示名从 p1 改成 p9，身份不变；把范围改成 $[10,22)$，身份变化。即使新旧组件都叫 p1，旧关系也不能因此被视为新关系。

这里有一个需要注意的原稿接口。第 2.6.1 节和附录 A 保留 24 个不能精确对齐整词的组件，依赖字符残差恢复身份。因此仅用 token 三元组不一定能表达全部规范对象。理解实现时应以原文字符范围、原生类型和文档身份为准，把 token 表示看成映射。原稿形式定义的补全建议已列在质量报告 Q-03。

### 2.2 CDCP 的关系是完整超边

CDCP 允许非空源集合共同指向一个目标。

$$
h=(S,c_j,\ell),\qquad S\ne\varnothing.
$$

$S$ 是组件集合，不是把成员串成一个新跨度。源集合按位置规范化，顺序规范化不改变成员身份。匹配要求全部源成员、目标和标签同时正确。

**教学例子。** 金标只有 $h=(\{a,b\},c,\mathrm{Reason})$。预测出 $(\{a\},c,\mathrm{Reason})$，得到一个 FP，同时完整金标仍产生一个 FN。若又预测 $(\{b\},c,\mathrm{Reason})$，就有两个 FP 和一个 FN，不能得到两个 TP。

严格身份与自然语义在这里分开。完整的 $\{a,b\}$ 支持 $c$，不推出 $a$ 单独对 $c$ 毫无意义。第三章不把这类未单独标注的真子集强行当语义 NONE；第四章完整对象评分器却可以将其标为精确匹配负例。两者监督问题不同，不矛盾。

### 2.3 合法图不是统一的树

合法结构集合记为 $\mathcal G_A$，$A$ 表示冻结的语料协议。最基本的条件包括跨度在原文内、类型合法、关系端点存在和标签合法。树结构、无环性、跨段限制并不是所有语料通用的真理。

AAEC 在文稿中枚举同文档不同组件的有向对，不依据 stance 额外补边。CDCP 的源集合遵守所选组件序列上的连续范围规则，目标不属于源集合。这里“连续”不是原文字符无间隔，而是在最终被选择的组件序列里没有夹着未纳入源集合的组件。

这一点在全局求解时尤其重要。组件选不选会改变源组是否连续，不能只在候选构建时检查一次就不管。

### 2.4 自回归生成与 LoRA 在本文中的作用

生成器逐 token 产生序列化的组件和关系。

$$
P_\theta(Y\mid D)=\prod_{t=1}^{L}P_\theta(y_t\mid D,y_{<t}).
$$

它表示当前输出 token 依赖原文和已经生成的前缀。概率乘积会受长度和字段顺序影响，因此完整序列概率高并不直接等于严格图抽取正确。

训练通常使用回答 token 上的平均负对数概率。**教学例子**中，两个正确 token 的概率分别是 0.5、0.8，其平均损失是 $(-\log0.5-\log0.8)/2\approx0.4581$。提高正确输出的概率会降低损失；这并不自动保证每个关系对象都满足结构约束。

LoRA 的参数化为

$$
W=W_0+\frac{\alpha}{r}BA,
\quad A\in\mathbb R^{r\times d_{in}},
\quad B\in\mathbb R^{d_{out}\times r}.
$$

$W_0$ 冻结，只训练较小的 $A,B$。**尺寸教学例子**中，若输入输出维度都为 4096、秩为 16，一个低秩分支有 $16\times4096+4096\times16=131072$ 个参数，而完整矩阵有 $4096^2=16777216$ 个参数。这个例子只解释低秩结构，不是本文模型总参数量的复算。

论文继承 Qwen2.5-7B-Instruct 和专项适配基础，主配置 rank 16、alpha 32。LoRA 降低训练参数量，但新增视图、辅助头及评分器仍可能增加总计算成本，不能由“参数高效”直接推出“系统更快”。

### 2.5 严格 F1 和聚合口径

对完整组件或关系分别统计

$$
\mathrm{Precision}=\frac{TP}{TP+FP},\quad
\mathrm{Recall}=\frac{TP}{TP+FN},\quad
F_1=\frac{2TP}{2TP+FP+FN}.
$$

**教学例子。** $TP=6,FP=2,FN=4$ 时，Precision 为 75%，Recall 为 60%，F1 为 $12/18=66.67\%$。漏掉一个超边成员可能同时产生错误预测与未命中金标，所以不能只按“有几个端点正确”给关系部分分。

micro-F1 先合并对象计数再算，和逐文档 F1 平均不同。**教学例子。** 文档甲有 $TP=9,FP=1,FN=1$，F1 为 90%；文档乙有 $TP=0,FP=1,FN=1$，F1 为 0。逐文档均值为 45%，而合并计数为 $TP=9,FP=2,FN=2$，micro-F1 为 $18/22=81.82\%$。

本文先在每个种子下合并全体测试文档，再得到该种子的 micro-F1，最后对三个种子报告均值和样本标准差。把三个种子的计数全部合并后算一个 F1，又是另一个量，不能要求它与均值处处完全相同。

### 2.6 公共协议如何减少混杂

AAEC 保留 319 篇训练文档和 80 篇测试文档；CDCP 保留 580 篇训练文档和 150 篇测试文档。重复处理在训练侧完成，测试全部保留。测试金标不能进入增强、校准、阈值选择或候选补回。

三折 OOF 用来生成评分器训练候选。简单说，一篇源文档的候选必须由没有训练过该源及其增强视图的生成器产生，否则评分器看到的错误分布可能过于乐观。评分器数据再分为拟合、校准、策略用途，不能为了“多用数据”把后两者标签又并回拟合池。

主要关系比较族有七组，乘两个语料共 14 项。Holm 校正处理同时尝试多项比较带来的误报问题。**教学例子**中，若三个原始 p 排序为 0.01、0.03、0.04，相应逐步调整得到 0.03、0.06、0.06。在 0.05 标准下，只有第一项通过。一个未调整的区间不跨零，仍可能无法通过多重比较校正。

本文表 3-4 的成对收益就是这种阅读情形。CI 是单项区间，p 却按 14 项主要族调整，不能用前者绕过后者。由于原始文档级重采样输入未随本次材料读取，本讲解只解释其报告方法，不声称复验了全部 p 和 CI。

## 第三章 增强与成对学习的详细讲解

### 3.1 先分清继承模块与新增损失

第 3.2 节保留全局和结论专项低秩分支。

$$
h'_t=W_0h_t+\frac{\alpha}{r}B_gA_gh_t
+g_t\frac{\alpha}{r}B_cA_ch_t.
$$

$g_t\in\{0,1\}$ 决定结论专项分支是否开启。字段按 id、type、span 排列，只有可见前缀中的类型完整生成后，相应后续字段才开启专项分支。AAEC 对 Claim/MajorClaim，CDCP 对 Policy/Value 触发；输入阶段和关系区域不触发。

**教学例子。** 当前前缀刚输出完一个 Claim 的 type，开始输出 span，$g_t=1$；若还在读取原文或尚未完成 type，$g_t=0$。它不会看到未来金标类型后倒过来影响已生成的字段。

连续提示由固定线索词触发，句子头学习输入句子是否与结论类金标范围相交。这些是继承基础。原文目标为

$$
\mathcal L_{ICIC}=\mathcal L_{gen}+0.5\mathcal L_{sent}.
$$

**教学例子。** 若生成损失 1.0、句子损失 0.2，继承目标为 1.1。后面的新增损失加在这个基础上，不替代原文的完整生成监督。

### 3.2 为什么要定义关系影响域

选定改写集合 $A\subseteq C$ 后，一个因素 $\omega=(S,v)$ 表示完整源集合与目标的端点组合。$V_\omega=S\cup\{v\}$ 是这项因素涉及的全部组件。

在声明的可审核宇宙 $\Omega_{sem}(C)$ 中，影响域为

$$
\mathcal D_A=\{\omega\in\Omega_{sem}(C):V_\omega\cap A\ne\varnothing\}.
$$

这条式子回答“哪些因素至少碰到一个改写组件”。它同时包含已有正关系和合格的 NONE 因素。全部端点位于 $A$ 内叫内部因素，部分位于 $A$ 内叫跨边界因素。

用原文表 3-1 的身份说明，若教学观察集合取 $A=\{T3,T4\}$，T4→T3 是内部正关系，T5→T3 和 T6→T3 是跨边界正关系，T4→T7 是跨边界 NONE。这个集合用于解释分类，不能冒充该文档自动增强中心算法实际输出的集合。

“完整”始终相对于声明宇宙。AAEC 枚举合法有向组件对；CDCP 保留全部金标超边，再补有限的至多三源候选组，超过三源的金标不被截断。这不等于枚举所有可能跨度或所有组件子集。

### 3.3 语义未知为何必须单列

对 CDCP 金标 $h=(\{a,b\},c,\mathrm{Reason})$，若 $\{a\}\to c$ 没有单独正标注，论文把这类非空真子集放入语义未知集合 $U_{sem}$。

$$
\Omega_{sem}=\Omega\setminus U_{sem}.
$$

它们不参与语义关系头的 NONE 监督，也不参与对应的语义审核与对齐。若原始标注明确存在单源正关系，正标注优先，不能因为它恰好是另一个超边的子集而屏蔽掉。

**教学计数。** 某个因素宇宙有 12 项，2 项属于上述未知子集，则可审核宇宙剩 10 项。说“完整审核了 10 项”成立，说“全部 12 项都已经证明稳定”不成立。未知应单独记录。

### 3.4 标注输运解决地址变化

增强模型只输出组件 ID 到替换文本的映射。程序依据原字符槽位回填全文，重新分词，并建立组件双射

$$
\phi:C\longrightarrow C'.
$$

所有组件的新坐标都要重算，关系全部端点通过 $\phi$ 更新。$\phi$ 是组件到组件的对应，不是 token 到 token 的一一对应。

**坐标教学例子。** 原文有组件 a 在 $[0,4)$、只读组件 b 在 $[6,10)$。把 a 的四个字符替换成七个字符，后面未改文字整体右移 3。a 变成 $[0,7)$，b 变成 $[9,13)$。关系 a→b 的两个端点都必须指向更新后的对象，不能只更新 a。

在无重叠冲突、双射成立且全部端点正确输运时，组件数、类型和关联结构保持。这是第三章性质一。但“保留同一张标注图”不证明改写后的语言还支持同样的标签，后者依靠语义检查和实际任务评价。

### 3.5 掩码究竟屏蔽什么

组件含义变化、待定或形式失效，会导致整个变体拒绝。通过组件检查后，默认关系审核集合 $J_A\subseteq\mathcal D_A$ 包含全部受影响正关系，并按固定规则抽取内部、跨边界 NONE 各至多 4 项。没有审核的 NONE 不能直接当作稳定。

关系掩码 $m_R(\omega)=1$ 至少需要原标签被认可、改写后状态相同、完整端点对应有效，以及所有端点的组件掩码通过。变化、待定、原标签分歧、未审核均屏蔽相应关系监督。

| 教学因素 | 审核状态 | 掩码 | 训练处理 |
| --- | --- | ---: | --- |
| 内部 Support | 原新都认可 | 1 | 参与标签监督和对齐 |
| 跨边界 Support | 改写后待定 | 0 | 不继承，也不改成 NONE |
| 内部 NONE | 原新都认可 | 1 | 参与 NONE 组监督和对齐 |
| 跨边界 NONE | 没抽到审核 | 0 | 保留未审核身份 |
| 联合源未知真子集 | 语义未知 | 0 | 不进入语义审核和负例池 |

如果资源不足以检查全部受影响正关系，该视图不进入关系学习，但已经通过检查的组件仍可提供组件监督。完整筛选则要求声明域全部合格，失败就拒绝整例。两种策略改变的是数据接受方式，不应在成对损失消融里偷偷换掉。

### 3.6 辅助头读什么信息

设输入子词隐状态 $h_i(x)\in\mathbb R^d$，组件对应子词集合为 $B_x(c)$，全文输入结束处的状态为 $h_{end}(x)$。组件表示和类别分布为

$$
u_c(x)=\operatorname{MeanPool}_{i\in B_x(c)}h_i(x),
\quad p_C^x(c)=\operatorname{softmax}f_C([u_c(x);h_{end}(x)]).
$$

$u_c$ 是 $d$ 维向量，拼接后是 $2d$ 维，输出维度等于语料组件类别数。金标跨度用于定位监督，但金标类型不作为头的输入。

为什么拼接全文末状态？因果模型中较早 token 的状态只看见左边，末状态提供全文上下文通道。它没有改变因果注意力，也不是偷读金标回答。原稿特别要求在回答开始前取状态。

关系分布使用源成员均值、目标表示、全文状态和位置等特征。

$$
p_R^x(S,v)=\operatorname{softmax}f_R(
[\operatorname{MeanPool}_{c\in S}u_c(x);u_v(x);h_{end}(x);\eta(S,v)]).
$$

$\eta$ 包含源成员数、源起止位置摘要及目标位置，不包含金标类型或关系标签。关系头对 AAEC 输出相应关系状态及 NONE，对 CDCP 输出 Reason/Evidence/NONE。

**形状教学例子。** 若表示维度暂取 $d=2$，两个源向量为 $(1,3)$、$(3,1)$，池化后为 $(2,2)$；再拼接目标向量、全文向量和位置特征送入 MLP。这个均值接口能接不同源数，但会压缩成员细节，其表达能力仍需实验判断，不能由公式本身证明足够。

### 3.7 JS 对齐在做什么

JS 散度衡量两个类别分布差异。

$$
m=\frac{p+q}{2},\qquad
\operatorname{JS}(p,q)=\frac12\operatorname{KL}(p\Vert m)
+\frac12\operatorname{KL}(q\Vert m).
$$

**数值教学例子。** 原文预测 $p=(0.8,0.2)$，改写预测 $q=(0.6,0.4)$，中点为 $m=(0.7,0.3)$。用自然对数，$KL(p\Vert m)\approx0.02573$，$KL(q\Vert m)\approx0.02258$，JS 约为 0.02416。两个分布完全一样时 JS 为 0。

组件对齐范围是改写组件加上受影响正关系连接的只读端点，再与通过组件检查的集合取交。

$$
A^+=A\cup\bigcup_{\omega\in\mathcal D_A:y_\omega\ne NONE}V_\omega.
$$

NONE 关系进入关系对齐，但不会仅因为数量很多就把所有远处组件都加进组件对齐。组件项在有效 $A^+$ 上平均，空集合取零。

关系项先将合格因素分成正关系组 $D_+$ 和 NONE 组 $D_0$，组内平均，再对非空组平均。

$$
\mathcal L_R^{align}=
\frac{1}{|\mathcal B|}\sum_{b\in\mathcal B}
\frac{1}{|D_b|}\sum_{\omega\in D_b}
\operatorname{JS}\bigl(p_R^x(\omega),p_R^{x'}(\phi\omega)\bigr).
$$

**权重教学例子。** 一项正关系的 JS 为 0.08，九项 NONE 的 JS 都为 0.01。直接平均是 $(0.08+9\times0.01)/10=0.017$；组间等权是 $(0.08+0.01)/2=0.045$。后者防止大量 NONE 仅靠数量淹没正关系。若只有一个非空组，就只平均该组，不给空组补假样本。

两个视图都保留梯度，不把其中一边强行固定成永远正确的教师。这样能共同调整共享表示，但也引出下一步必须处理的共同错误问题。

### 3.8 为什么一致性还需要标签锚定

若正确类别是第二类，但两个视图都预测 $(0.9,0.1)$，JS 为 0，说明高度一致，却都错了。正确标签交叉熵是 $-\log0.1\approx2.3026$，它会推动正确类别概率提高。

论文因此为原文和通过掩码的增强因素保留标签监督。组件项按组件平均，关系项沿用正关系/NONE 两级平均，两项等权相加。原文使用全部原生组件和可审核因素，增强文只使用掩码为 1 的因素。

这解释了为什么 NoPair 是必要对照。它保留相同视图、掩码和标签监督，只关闭分布对齐。没有该对照，完整训练增量可能来自更多可靠标签、辅助头或数据，而不是成对项。

### 3.9 整个损失怎样算

源文档 $d$ 有 $m_d$ 个接受视图，辅助头监督为

$$
\mathcal L_{heads,d}^{sup}=
\frac{S(x_d,G_d)+\sum_{j=1}^{m_d}S_{m_j}(x'_{dj},\phi_jG_d)}{1+m_d}.
$$

两个对齐项分别先按因素平均，再按同源接受视图平均。总损失为

$$
\mathcal L_d=\mathcal L_{ICIC}(x_d,G_d)
+\mathcal L_{heads,d}^{sup}
+0.5\mathcal L_{C,d}^{align}
+0.5\mathcal L_{R,d}^{align}.
$$

**完整教学复算。** 某源有两个变体。原文继承损失为 1.1；原文和两个变体的头监督分别为 0.9、0.6、1.2，则头监督平均为 0.9。两个变体的组件对齐为 0.02、0.06，均值 0.04；关系对齐为 0.04、0.08，均值 0.06。因此总损失为 $1.1+0.9+0.5\times0.04+0.5\times0.06=2.05$。

批内再按源文档平均。一个源有两个变体、另一个没有变体，不会直接按三个文本对一个文本的比例赋权。代价是头监督中原文的占比随变体数变化，但原文完整生成损失保持一次完整权重。

默认增强文不承担整图生成损失。这保证关系掩码真的有效，不会从另一条损失路径把未知标签重新引入。辅助头只在训练使用，推理评分器另行训练。

### 3.10 梯度往哪里走

原文生成与句子监督更新其对应继承模块。组件头、关系头和成对项通过输入表示更新全局 LoRA；输入阶段专项门控关闭，因此对齐项不直接训练结论专项分支。基础权重冻结，两个视图的隐藏状态都不能被意外 detach。

附录 F.2 的接口检查应确认表示来自回答前、金标标签未作为输入、计算图连通和参数具备更新资格。一次零梯度不一定表示断路，因为该输入的损失可能恰好为零；需要非零对齐损失的受控输入检验。这类程序检查仍不替代任务效果实验。

### 3.11 两条性质的作用范围

标注输运保持性质来自双射和端点逐一映射，保证图对象没有被错误搬运，不保证语言含义。

逐因素预测稳定性质使用类别间隔。设正确类为 $y$，原分布间隔为

$$
\gamma=p_y-\max_{k\ne y}p_k>0.
$$

若 $\|p-q\|_\infty<\gamma/2$，则增强分布仍以 $y$ 为最大类。这里用 $\gamma$ 重命名原稿本段的间隔符号，避免与第四章接受阈值 $\delta$ 混淆。

**教学例子。** $p=(0.8,0.2)$，正确类为第一类，间隔 0.6。$q=(0.6,0.4)$ 的最大坐标变化 0.2，小于 0.3，第一类仍获胜。该条件逐因素成立才有保证；全体因素平均 JS 下降，不能保证最差因素也满足条件。

## 第四章 依赖闭合修正的详细讲解

### 4.1 首先明确三个不同的评分或判断

第四章容易读错，是因为“评分”先后用于不同事情。

| 接口 | 对象 | 用途 | 是否直接保证严格正确 |
| --- | --- | --- | --- |
| 初始图排序 $E_{rank}$ | 一整张生成图 | 从已有候选中选起点 | 否 |
| 完整对象评分 $q_C,q_R$ | 一个具体组件或完整关系 | 为候选修改提供固定置信度 | 否，依赖训练和校准 |
| 最终严格计数 | 预测与金标完整对象 | 评价 TP/FP/FN 和 F1 | 是按该金标协议计算，但不能在线使用测试金标决策 |

训练辅助头还在这张表之外，它服务于第三章的类别监督与对齐，测试时移除。阅读时不能把这些概率和分数互换。

### 4.2 多候选为何先生成完整图再排序

默认有三组组件假设，一组贪心、两组采样。每组组件固定后生成其关系，形成完整图 $G_k=(C_k,R_k)$。关系阶段不能悄悄重新分割组件。

多个候选保留边界、类型和关系的竞争假设。若先只按组件分数挑一组，再只对这一组预测关系，可能丢掉原本能形成更好完整图的假设。

初始排序沿用

$$
E_{rank}(G)=0.4E_{dens}(G)+0.4E_{coh}(G)+0.2E_{val}(G).
$$

密度项考察指定覆盖节点获得多少经验证的入关系，相对阈值归一化并截断到 1；连贯项为关系语义验证的均值；合法项表示全部格式与协议检查是否通过。

**教学例子。** 若三个分量为 0.75、0.80、1，排序分为 $0.4\times0.75+0.4\times0.80+0.2=0.82$。但这是加权评分，合法性并不是自动硬门。排名第一的图仍须经过共同合法化，无法得到合法初始图就显式失败。

共同合法化仅做明确的坐标规范化、同一语义对象去重和 ID 重排，不猜边界、不随意删冲突对象或补金标边。它的改变必须单独记录，避免后处理能力被算到生成器头上。

### 4.3 候选宇宙包含什么

修正前固定三层集合。

$$
U=\text{跨度候选},\quad
V=\{(u,t):u\in U,\ t\in T^*(u)\},\quad
P=\text{完整关系候选}.
$$

$U$ 只有位置，$V$ 加入类型，$P$ 包含完整端点身份与关系标签。同一个跨度有两种候选类型，属于两个不同的带类型对象，但最终最多选择一个。

来源分为受保护部分和补充部分。合法初始图和成功解析候选中的合法对象受到保护，不因补充池上限而被裁掉；补充跨度、类型、源组由训练出的提案接口提供。默认补充跨度 64、每跨度前 2 类型，CDCP 完整源组和目标的补充预算有限。关系补充槽位上限与裁剪前预检也分别记录。

“槽位”是端点组合，“关系候选”还带标签。同一槽位的所有合法标签应一起保留，选哪个由后续决定；全不选相当于 NONE。一个源组的成员不会被展开成多个二元关系。

**组合规模教学例子。** AAEC 若有 10 个跨度、每个跨度 2 种类型，忽略兼容性时，有 $10\times9\times2^2=360$ 个有向端点槽位。如果再加两个关系标签，可产生 720 个带标签关系变量。实际默认池还要受兼容性、保护和提案预算约束，不能把这个宽松组合界冒充实际枚举量。

未入池的金标关系对当前修正器不可达。测试金标只用于事后覆盖分析，不能用于补回候选。离线 Oracle 也不进入在线决策；本文主要报告的是覆盖，不能自行添加没有报告的 Oracle 成绩。

### 4.4 冲突闭合为何要扩大删除集合

一次组件提议指定新增集合 $B$ 与主动删除集合 $D_0$。先抵消语义不变对象，再补齐所有与新增对象冲突的旧组件。

$$
D=D_0\cup\{c\in C:\exists b\in B,\operatorname{Conflict}(c,b)\},
\qquad C'=(C\setminus D)\cup B.
$$

**教学例子。** 旧组件 a 在 $[0,10)$、b 在 $[10,20)$，提议新增合并组件 m 在 $[0,20)$。即使提议最初只写删除 a，m 也与 b 冲突，因此最终必须删除 a、b。实际动作是 2→1，组件编辑成本为 3，不能伪称为插入一个对象。

主邻域支持 0→1、1→0、1→1、1→2、2→1，分别对应插入、删除、替换、拆分、合并。冲突闭合后再核对形态和三对象上限。单对象对照不能让名义插入经过扩张偷偷变成集合合并。

### 4.5 关系依赖闭合到底收集哪些关系

变化对象集合为 $A=D\cup B$。$P_A$ 收集冻结候选池中接触这些旧新对象的全部关系，包含入边、出边、原有正边和原本未选关系的槽位。

纯关系提议用 $S_R$ 表示，事务空间为

$$
P_{tx}=P_A\cup S_R.
$$

如果只是删除、增加、换标签或反向关系，$D=B=\varnothing$，由 $S_R$ 表达。二元反向需要正逆两个槽位都已在池中且当前合法，不能临时创造缺失的逆向关系。多源超边没有被定义为多目标反向。

**教学例子。** 旧组件 a 有 b→a 和 a→c 两条关系。将 a 替换为 a′ 后，两条旧关系都引用旧语义键，必须删除或重新构造；新 b→a′ 与 a′→c 分别是新对象，不能只检查 a 的出边。若还存在 d→e，且端点及合法性不受影响，它保持固定。

对 CDCP，某些事务外已选关系会因组件选择改变而失去连续性。论文采用最小合法化扩域，把这些已失效旧槽位加入事务空间，仍无法合法或超预算就拒绝。这保证返回图完整合法，但不会自动枚举所有新变合法的未选关系。

### 4.6 一个说明局部范围限制的重要例子

原稿第 4.3.2 节给出 a、b、c、t 的顺序。池中有 $h=(\{a,c\},t,\mathrm{Reason})$，但 b 被选在 a、c 中间，因此 h 当前不满足源组连续性。

若某次事务删除 b，h 的源组可能变得连续。可是 h 的端点 a、c、t 都没有变化，它不一定属于该事务的端点依赖域。若 $S_R$ 没有包含 h，该次事务不会自动选 h。

后续必须真的把 h 纳入纯关系提议、进入队列并通过分数、约束和剩余预算，才可能恢复它。全局模型则能同时决定删除 b 和选择 h。这说明“端点依赖闭合”不等于“每次把所有状态相关机会都搜遍”。

### 4.7 完整对象评分器为什么用 OOF

组件分数 $q_C(c\mid x)$ 估计该跨度和类型是否精确正确。关系分数 $q_R(r\mid x)$ 估计完整端点、类型、方向与标签是否精确正确。

若训练关系评分器时永远给它金标端点，它可能只学会在理想组件之间分类，遇到真实推理中的错误边界、碎片和类型错误就失真。因此使用 OOF 预测候选产生训练正负例，并保留两个训练配置的候选来源。

自然候选通常负例很多。拟合时可以对困难样本调整采样，但校准应保留自然分布，否则“0.8 概率”可能只是人工平衡样本中的含义。校准与策略选择数据分开，测试不参与选择。

对象分数和校准参数在搜索前冻结，缓存绑定完整语义键。当前图的度数、边数或动态重编码不改变同一对象分数。参数与生成器分开有助于接口隔离，但不保证两者错误在统计上独立。

缺分是“没有有效判断”，低分是“已经判断为不可信”。将 NaN 或未评估替换成零，可能让算法误以为删除一个真实对象有巨大收益。主规则拒绝触及缺分对象的事务，全池缺分时回退，部分缺分时按局部路径处理安全的范围。

### 4.8 固定效用从哪里来

对于对象族 $X\in\{C,R\}$，设 $0<\kappa_X<2$，单对象权重为

$$
a_X(o)=2q_X(o\mid x)-\kappa_X.
$$

全图效用为

$$
\Phi_X(G)=\sum_{o\in X(G)}a_X(o),\qquad
\Phi(G)=w_C\Phi_C(G)+w_R\Phi_R(G).
$$

主配置 $w_C=w_R=1$，组件 $\kappa_C=1$，AAEC 关系 $\kappa_R=1$，CDCP 关系 $\kappa_R=0.5$。系数在开发侧选定后冻结，不按当前图大小除以对象数。

**教学例子。** 当 $\kappa=1$，$q=0.8$ 的对象权重是 0.6，$q=0.3$ 的对象权重是 −0.4。若其他条件不变，新增前者增加效用，删除后者也增加效用。单对象权重为正的分界是 $q>\kappa/2$，所以 AAEC 关系对应 0.5，CDCP 对应 0.25。

这个阈值不是完整事务的充分接受条件。对象仍须满足端点、冲突、关系互斥、分项门和编辑预算等条件，整个增量还要超过 $\delta$。

为什么定义成 $2q-\kappa$？暂假设 $q$ 就是真实条件概率，利用 $FP=|X|-TP$ 和 $FN=|Y_X|-TP$，有

$$
\Phi_X(G)=(2-\kappa_X)\mathbb E[|Y_X|\mid x]
-\mathbb E[\kappa_X FP_X+(2-\kappa_X)FN_X\mid x].
$$

第一项不随所选图变化，所以最大化效用等价于最小化固定误检和漏检代价的期望。这用的是期望线性性，不要求对象正确事件彼此独立。

**代价教学例子。** 对一个真实概率 $q=0.3$ 的候选，$\kappa=0.5$ 时，选它的期望 FP 代价为 $0.5\times0.7=0.35$；不选它的期望 FN 代价为 $1.5\times0.3=0.45$。选择比不选好 0.10，恰好等于 $2\times0.3-0.5=0.10$。这体现降低 $\kappa$ 更重视漏检，但没有自动解决评分错误。

该目标是代价敏感代理，不是期望 F1。结构约束和事件依赖也不能从一个简单边际阈值中消失。

### 4.9 一次接受判断怎样逐项计算

候选状态必须合法、未超预算，并满足

$$
\Delta\Phi_C\ge0,\qquad
\Delta\Phi_R\ge0,\qquad
\Delta\Phi>\delta>0.
$$

默认 $\delta=0.20$，最后一个比较是严格大于。

**完整事务教学例子。** 使用 $w_C=w_R=1$、两族 $\kappa=1$。旧组件 a 的 $q_C=0.65$，新组件 a′ 的 $q_C=0.80$，组件增量为 $(2\times0.80-1)-(2\times0.65-1)=0.30$。一条旧关系的 $q_R=0.80$，对应新关系的 $q_R=0.85$，关系增量为 0.10。总增量 0.40，大于 0.20，两个分项都非负。在其他合法性和预算条件通过时可以接受。

这里组件成本是一次删除加一次新增，$d_C=2$；关系成本也是旧关系删除、新关系新增，$d_R=2$。边界变了却沿用 ID，并不能把它算成零编辑。

再看另一个教学提案。新组件 $q_C=0.95$，组件增量为 0.60；新关系 $q_R=0.70$，关系增量为 −0.20。总增量仍为 0.40，但关系分项下降，必须拒绝。这说明分项门限制用一类代理收益抵偿另一类明显损失。

它也可能拒绝真实有益的修改，因为分项分数只是估计。保守门是设计选择，不是 F1 单调定理。

### 4.10 固定评分为什么可以精确做差

共同对象在前后状态里的分数一样，因此相消。

$$
\Delta\Phi_X=
\sum_{o\in X(G')\setminus X(G)}a_X(o)
-\sum_{o\in X(G)\setminus X(G')}a_X(o).
$$

**教学例子。** 旧图有权重 0.3、0.5、0.6 三个对象，新图保留 0.5、0.6，删 0.3、加 0.8。旧和为 1.4，新和为 1.9，增量 0.5；差分同样为 $0.8-0.3=0.5$。如果保留对象在搜索中被重打成新分数，就不能再只看删增部分。

依赖闭合保证关系差集完整。如果换了端点却只计算新增边，不计算失效旧边，就不是精确差值。命题的价值在于让实现和账本一致，不是证明选中的图语义正确。

### 4.11 局部 ILP 在求什么

局部路径先确定提议后的组件集合 $C'$，组件选择 $z_c=I[c\in C']$ 固定；关系变量 $y_r\in\{0,1\}$ 决定是否选关系。目标为固定组件效用加所有选中关系权重。

主要约束分别表示

$$
\sum_{t\in T^*(u)}z_{u,t}\le1,
\qquad z_c+z_d\le1\quad\text{若二者冲突},
$$

$$
y_r\le z_c\quad\forall c\in Ends(r),
\qquad \sum_{r\in\Gamma_s}y_r\le1.
$$

第一条同跨度只能选一种类型；第二条排除冲突组件；第三条要求关系全部端点存在，超边全部源成员也在其中；第四条使同一槽位的标签互斥。事务外关系固定，整图仍须满足语料约束。

**教学小问题。** 源 a、目标 b 均被选中，同一槽位有 Support 权重 0.6、Attack 权重 0.2。互斥约束使求解器最多选一个，在没有其他限制时选 Support。若 b 没被选中，则两条关系都必须为 0，不能为了高关系分凭空连接不存在的端点。

若协议要求无环，可以用拓扑序变量 $o_c$ 和大 M 约束

$$
o_v\ge o_u+1-M(1-y_{u,v,\ell}).
$$

关系被选时强制目标序号更大；未选时放松。**教学例子。** 同时选 a→b 与 b→a 会要求 $o_b\ge o_a+1$ 且 $o_a\ge o_b+1$，矛盾，所以不能成环。协议没有要求无环时，不能随意加入这条约束。

编辑成本和效用门也要进入求解，不能先求一个违规最高分解，再据此说没有任何合格解。超时有 incumbent 只表示已有可行解，未经最优证书不能称最优。求解后还需复核再提交。

### 4.12 编辑预算和执行预算不是同一个量

局部关系编辑成本是对称差

$$
d_R=|R\triangle R'|,
$$

线性实现可写为原先选中的关系被删计 1，原先未选的关系被加入计 1。组件为 $d_C=|D|+|B|$。

外层默认每轮至多 32 次尝试、3 次接受，最多 4 轮，因此最多 128 次尝试、12 次接受；组件累计预算 24，关系累计预算 96。一次尝试是否接受，与它消耗多少模型调用、求解时间和实际编辑都不同。

**教学例子。** 某关系先被删，再被加回。终态净变化是 0，但局部累计编辑是 2。失败提议消耗尝试、时间和调用，却不增加已提交对象编辑量。不能只看最后一张图就断言过程中没做事。

原子提交表示完整候选一起生效，失败恢复最近合法图及其引用状态，已花时间不退。no-op 是独立选择，不需要满足正增益门，不能为了满足“修改”而强行改变合法初始图。

### 4.13 集合动作的存在性证明怎样读

命题声称存在一些状态，单对象严格改进走不过，而集合替换能走过。这是可达性陈述，不是平均 F1 优势。

原稿 B.6 给出旧总效用 0.8、新效用 1.0 的例子，增量正好 0.20。它若使用默认严格门 $\Delta\Phi>0.20$，就不能接受。因此需要声明更小的演示阈值，或改一组数值。

**修订教学构造，不是实验。** 两个兼容旧组件各有权重 0.30，新组件权重 0.90，并与两个旧组件都冲突，无关系对象。删除一个旧组件降分 0.30；直接插入新组件不合法；单对象路径不能把冲突扩张后的 2→1 合并偷偷计作单对象。集合删除两个旧组件、加入新组件后，效用从 0.60 到 0.90，增量 0.30，大于默认 0.20；关系分项保持 0，组件成本 3，预算允许时可以通过。

这个构造证明某种障碍可以被集合动作跨过。它没有说明真实候选中这种情况多不多，也没有说明评分与金标一致，更不保证当前实验会获得额外 F1。

### 4.14 有限终止为什么不等于足够好的结果

候选宇宙有限，合法状态数也有限。每次接受都严格提高同一个固定 $\Phi$，就不可能再次访问以前的状态，因此接受序列有限。

实际流程通常先被轮数、尝试、编辑或时间预算截断。有限终止只保证不会无限接受循环，不保证穷尽全部邻域，也不保证最后达到全局最优或高 F1。若分数或 $\kappa$ 在中途改变，该证明的前提也随之改变。

### 4.15 全局模型多做了什么

全局路径把全部组件变量 $z_v$ 和关系变量 $y_r$ 一起决定，目标仍是同一固定效用。对 CDCP 源连续性，若 $w$ 在超边源成员的最左和最右位置之间、又不属于源集合，加入

$$
y_h+z_w\le1.
$$

**教学例子。** $h=(\{a,c\},t,Reason)$ 中间有候选 b，约束是 $y_h+z_b\le1$。可以选 b 而不选 h，也可以删 b 并选 h，但不能两者同时选。这样连续性随最终组件状态变化，得到准确表达。

全局分项门相对初始图 $G_0$，编辑量按终态相对 $G_0$ 的净差；局部分项门相对每一步当前图，编辑量累计。因此使用相同数字预算，不代表两者拥有完全相同的可行路径。

每个局部终态满足全局的分项门且净编辑不超过累计编辑，所以属于全局可行域。但某个全局可行解可能需要局部过程中先降一个分项，局部规则不允许经过。这解释了为何全局与局部可能有不同终态。

初始对象被保护，$G_0$ 本身满足全局约束且净编辑为 0，所以全局模型应始终可行。若求解器报告数学不可行，首先应查实现或数值错误，不能解释为“没有值得修改的图”。没有严格改进时直接返回 $G_0$。

### 4.16 I1 路由与返回身份

主配置先查评分齐备，再以 $n=|V|+|P|$ 判断规模。$n\le2500$ 用全局，超过则用有界单对象局部；无环序变量、约束数量和破同分调用另行记录。AAEC 与 CDCP 时限分别为 3 秒、5 秒。

全局有最优证书时仍要检查严格增益门；超时有改进 incumbent 且通过全部复核，可以返回“可行非最优”；没有合格改进、求解失败或全部评分失败，则返回初始图并保留状态码。默认不在同一预算里再偷偷追加局部补救。

当前模拟主测试全部小于 2500，因此 I1 的主表与 Global 重合。这里的最优是有限候选和代理目标下的最优，不包括候选池外对象，也不等于真实 F1 最优。

### 4.17 代理效用提高为什么仍可能降低 F1

记真实正确预测数为 $T$、预测数为 $P_0$、金标数为 $Q$，则 $F=2T/(P_0+Q)$。一次修改后

$$
F'-F=\frac{2\Delta T-F\Delta P_0}{P_0+Q+\Delta P_0}.
$$

它来自分式直接通分。符号告诉我们，真实变化同时取决于正确数变化和预测数量变化；评分器不知道测试时真正的 $\Delta T$。

**教学例子。** 起点 $T=6,P_0=8,Q=10$，$F=2/3$。删除两个错误预测时 $\Delta T=0,\Delta P_0=-2$，F1 增量为 $(0-(2/3)\times(-2))/16=1/12$，从 66.67% 到 75%。若删掉的是唯一正确关系，即使同时删掉很多误边，F1 也可能降到零。

文稿 CPU 例子恰好呈现后一种风险。种子 17 的计数 $1/54/5$ 变成 $1/19/5$，F1 从 $2/61=3.28\%$ 到 $2/26=7.69\%$；种子 29 的 $1/45/5$ 变成 $0/17/6$，F1 从 $2/52=3.85\%$ 到 0。规则减少了误边，但不保证保住正确关系。

这组案例在文稿中属于 CPU-BIO-SGD 与固定规则处理，不能替代主模型事务验证。它们适合解释真实指标边界，不能证明主算法运行过。

### 4.18 评分指标该看哪里

AUROC 主要看排序区分，AP 更直接反映正例稀少时的精确率召回表现，Brier 衡量概率与二元标签的平方误差，ECE 汇总分箱后的置信度偏差。

**Brier 教学例子。** 两个对象分数为 0.8、0.2，标签为 1、0，平均平方误差为 $[(0.8-1)^2+(0.2-0)^2]/2=0.04$。但整体 Brier 或 ECE 很好，不等于真正会被接受的高分区域可靠；大量低分负例可能占据统计量。

所以图 4-3 和表 4-8a 还看决策区域。模拟数据中 CDCP 关系正例为 705/41818，整体 ECE 为 0.0059；门限 0.25 以上有 714 个候选，其中 399 个正确，区域精确率约 0.559、平均 q 约 0.512。两组数字一起看，比只报一个很小的 ECE 更有解释力。

被搜索最终加入的关系又经过端点、约束与预算筛选，其精确率不必等于候选决策区域精确率。例如主配置 CDCP 新增关系为 29/35 正确，不能直接用这一数值替代原始评分器质量。

### 4.19 实验比较的真正含义

模拟结果中，T1/I1 相对 T1/I0 提高 4.48 / 8.37 pp，并通过主要校正。完整配置相对 RelationOnly 只多 0.67 / 1.35 pp，校正后未确认；Single 相对 Sequential 未确认；SetLocal 与 Single 相同；Global 相对局部的小差值区间跨零。

这意味着论文最有支持的主张是完整推理配置相对继承推理有增量，不能把全部增量归于组件可变、共同接受或集合动作。完整推理相对等预算重生成的点估计更高，但联合区间跨零，也不能写成稳定显著优势。

主流程缺分为 0，所以 MissingLow 与主配置相同是空效应检查；它不能证明缺分保护提高了主实验 F1。NoRisk 与主配置关系 F1 相同，说明当前主条件下风险策略没有改变该终态指标，不等于所有评分条件都不需要风险控制。

图 4-4 和表 4-15 的弱评分 v0 在不同条件下无法通过开发 TP 保留要求。即使将 $\kappa_R$ 降至 0.5，开发原 TP 损失仍为 41%，因此返回初始图。其候选和评分与主版本不同，不能把两者当作同一冻结输入只改一个参数的消融。

### 4.20 计算成本与实际适用性

表 4-9 的模拟报告中，AAEC T1/I0 端到端均值为 18.26 秒，T1/I1 为 32.17 秒；CDCP 从 25.56 秒到 44.89 秒。评分列分别达到 12.93 和 17.92 秒，不能把成本问题全部归于 ILP。

等预算重生成匹配追加调用和 token 上限，但 CPU 求解等费用单列，因此“相同调用预算”不等于完全相同的端到端时延。全局求解有证书可能有工程价值，但当前数据并未显示它必然获得更高 F1。

主方法下一步需要的是真实候选、评分和求解轨迹。现在的严格规约有助于定义什么应被验证，却不能代替实际运行证据。

## 第五章 两阶段综合分析的详细讲解

### 5.1 四格怎样分离条件增量

将严格关系 F1 记为 $F_{ti}$，其中 $t\in\{0,1\}$ 是训练配置，$i\in\{0,1\}$ 是推理配置。四格模拟结果为

| 语料 | $F_{00}$ | $F_{10}$ | $F_{01}$ | $F_{11}$ |
| --- | ---: | ---: | ---: | ---: |
| AAEC | 65.18 | 68.81 | 69.90 | 73.29 |
| CDCP | 38.76 | 43.65 | 46.72 | 52.02 |

固定 I0 的训练增量是 $F_{10}-F_{00}$，固定 T1 的推理增量是 $F_{11}-F_{10}$。完整组合相对起点为 $F_{11}-F_{00}$。这是沿一条路径做差，不表示两个模块统计独立。

不同训练检查点可以产生不同候选，因为候选质量本身属于训练效果。推理消融则固定同一 T1 检查点、候选与评分，才能归因于推理变化。不要把“所有比较都固定候选”作为不加区分的要求，否则会把训练改变候选的效果也排除掉。

### 5.2 交互的计算与解释

交互定义为

$$
I=(F_{11}-F_{10})-(F_{01}-F_{00}).
$$

它问新训练下的推理增量，是否不同于旧训练下的推理增量。

AAEC 推理增量分别约 4.48 和 4.72，交互约 −0.24；CDCP 分别约 8.37 和 7.97，交互约 +0.40。原稿区间分别为 $[-0.55,0.06]$ 和 $[-0.70,1.54]$，都跨零。

因此可以说两阶段都形成条件增量，组合在当前模拟表中更高；不能说已经证实稳定的超加性协同。AAEC 的微小负交互也不等于两模块互相破坏，它可以对应恢复空间部分重叠，也可能只是抽样波动。

用附录 H-5 未舍入计数复算，AAEC 总增量为 8.1036 pp，CDCP 为 13.2630 pp。显示均值四舍五入后相减或分项差值相加，可能与报告末位不同。统计量应先按定义在全精度上计算，再显示。

### 5.3 对象成员分析为什么比只看分数更具体

把每个正确关系视为由“文档、种子、完整语义键”确定的成员。起点已正确的集合、训练独立恢复的集合、推理独立恢复的集合、组合新恢复的集合可以逐对象做交并差。

表 5-4 的 AAEC 恒等式为

$$
1582+1+93+36+1-0-9=1704.
$$

依次表示起点 TP、共同恢复、训练独有、修正独有、组合独有、丢失单路恢复和丢失起点 TP。CDCP 对应

$$
293+2+35+26+3-0-1=358.
$$

这些计数是三种子对象记录合计，不是一个模型在一份语料上拥有 2427 条不同原生金标关系。AAEC 原生金标是 809 条，三个种子才形成 2427 份评价对象供给。

对象分解展示“修复了谁”，但只分解 TP，不能直接解释全部 F1。F1 同时受 FP 和预测数量影响。比如训练和推理都可能找到相同数量的新 TP，却因为一个删掉更多 FP 而得到不同 F1。

表 4-6 可以补充这种解释。AAEC 从 T1/I0 的 1670 个 TP 出发，完整推理恢复 37、误删 3，得到 1704。CDCP 从 330 出发，恢复 29、误删 1，得到 358。这是相对 T1/I0 的推理净变化，与表 5-4 相对 T0/I0 的四格成员分解参照不同，不能交叉替换起点。

### 5.4 候选恢复链告诉我们瓶颈在哪里

表 4-5 的三种子关系链为

| 阶段 | AAEC | CDCP |
| --- | ---: | ---: |
| 金标完整关系供给 | 2427 | 756 |
| 全部端点入池 | 2411 | 734 |
| 完整关系入池 | 2391 | 705 |
| 评分过门 | 1788 | 399 |
| 过门且端点被选 | 1704 | 358 |
| 最终 TP | 1704 | 358 |

AAEC 完整关系候选覆盖约为 98.52%，CDCP 约为 93.25%，已经相当高；但后续评分与终态选择仍丢掉很多关系。因此“候选池含有正确关系”只是可达性的必要条件，不是已经恢复。

最终 TP 除以金标供给得到关系召回率，AAEC 约 70.21%，CDCP 约 47.35%，不能把这个比例叫作表 5-2 的 F1。F1 还需要 FP。表 4-5 最后两列相同，只说明这批模拟结果在这两个阶段之间没有额外损失，不是算法总能如此的定理。

### 5.5 首个阻断表与覆盖链为什么不一样

表 5-5b 从“最终未命中的金标关系”出发，按预定顺序找第一处障碍。AAEC 为

$$
1704+588+135=2427,
$$

即最终 TP、终态端点缺失、评分未过门。CDCP 为

$$
358+272+2+124=756,
$$

另有 2 条完整槽位未入池。

这里先检查终态端点，所以一条关系即使也不在池中，只要终态端点缺失，就会被归到前者。因而首个阻断中的“未入池”不需要等于覆盖链的总候选遗漏。它们是在不同条件下计数。

这是一种便于定位的互斥归类，不是因果分解。把所有缺失端点补回，也未必能恢复全部这些关系，因为它们可能还存在评分或约束问题。未评分和超时为零，也只说明当前记录没被这两类首先阻断。

### 5.6 CDCP 源成员数为何要分组

原生测试 252 条关系中，单源 218 条、双源 20 条、三源 6 条、四源及以上 8 条。多数是单源，所以总体 F1 可能掩盖长源集合的困难。

表 5-6 的完整配置单源、双源、三源、四源及以上 F1 分别为 53.26、49.45、59.90、15.02，均为三个种子的分组 F1 均值。三源只有 6 条原生关系，跨种子 SD 达 23.49，不能只看到 59.90 就说模型特别擅长三源。

四源及以上合计三种子 TP=3、FP=13、FN=21，合并后 F1 为 $6/(6+13+21)=15.00\%$，与逐种子均值 15.02% 略有差异并不矛盾。分组计数核对供给时使用 TP+FN=24，恰为 $8\times3$。

三源补充预算不会删除原有长超边，但会限制新增长源组合的召回机会。这个接口差别需要与评分质量分开分析，不能将长源失败全部归咎于求解器。

### 5.7 外部比较能说明什么

附录 G 的模拟系统结果中，UniASA 和 TextToText 的 AAEC 关系 F1 为 63.12、61.64，CDCP 为 36.51、34.79；完整系统为 73.29、52.02。相关检验是探索性系统比较，不在 14 项主要族中。

统一官方测试划分和严格评价器，解决了一部分口径问题。但骨干、训练组织、调优资源和表示能力仍不同，不能把 10—17 个百分点的全部差距解释成某一个新增模块的独立效应。

CDCP 外部适配最多表达三源，8/252 条四源以上金标受到接口上界限制，占 3.17%。这个比例是对象供给比例，不是可以直接从 F1 差距里扣除的常数。更完整的比较应同时报告全任务、共同可表示子集及成本，并维持各自身份。

### 5.8 第五章真正完成的综合

第五章把效果从一个“最高分”拆成三层。第一层是两个阶段的条件增量和交互；第二层是哪些完整对象被恢复或丢失；第三层是候选、评分、端点与源成员数形成的具体限制。

从当前模拟结果看，候选覆盖与决策区域评分比继续扩大集合动作更值得优先研究。这个判断来自当前链条与消融，不是对所有论辩任务的永久结论。

## 第六章 总结与展望的详细讲解

### 6.1 什么可以作为本文的研究结论

方法层面，论文定义了可靠对应因素上的训练接口，以及固定对象分数下的依赖闭合修正接口。它把原生对象身份、严格评价、成本和失败出口连接起来，这是其较清楚的技术框架。

结果层面，模拟表支持整套训练和整套推理的条件增量，完整配置为 AAEC 73.29、CDCP 52.02，相对继承配置增加 8.10 / 13.26 pp。四项主要阶段比较通过所报告的 Holm 校正。

机制层面，成对项的独立收益未通过家族校正，共同接受和集合动作未形成稳定优势，相对等预算重生成也未获得显著优势。论文应把这些结论与整套效果并列，而非藏在附录中。

来源层面，上述主结果仍是合成评审内容。文件内的“训练完成、验收通过、最优证书”等描述，不能在本次阅读中转成已验证的实际成果。

### 6.2 适用条件怎样从前文推出来

| 条件 | 若不满足会怎样 | 前文根据 |

### 6.3 后续工作应该怎样排序

第一步是完成真实主流程。保存实际增强输出、审核状态、掩码、训练检查点、OOF 候选、自然分布评分、求解与接受轨迹。先让规约真正产生可复算对象。

第二步是检验独立机制。固定视图和掩码比较成对项；固定候选和分数比较接受规则与动作范围；对没有确认优势的模块保留简化实现的可能，不把复杂度本身视为贡献。

第三步才是扩大范围。围绕长源集合提案、决策区域概率标度和低开销评分补充研究，并在有清楚划分的新语料上检验。CasiMedicos 的正文缺失和 ArgUNSC 的划分身份都要先解决，不能仅凭原文案例宣称医学或跨域泛化。

## 常见误读和正确解释

| 容易出现的理解 | 更准确的理解 |
| --- | --- |
| 组件含义不变，所以所有关系都不变 | 需要检查受影响的完整因素，尤其跨边界与 NONE |
| 原文到改写文 token 一一对应 | $\phi$ 对应的是组件，文字长度和 token 数可以变化 |
| NONE 就是所有语义上的无关 | 它依赖声明宇宙和用途，联合源未知子集不能机械当负例 |
| 成对学习让两次答案一样就够了 | 两次可能一起错，必须配合标签锚定 |
| 辅助头概率可以直接给推理使用 | 辅助分类与完整对象正确率的监督目标不同 |
| 依赖闭合就是把附近所有可能性都搜一遍 | 它收齐指定端点依赖及必要合法化范围，仍有候选和邻域限制 |
| 边界改了但 ID 没改，不算新关系 | 完整端点身份变了，旧删新加都要计费 |
| 最优解就是真实最好答案 | 只是给定候选、约束和代理目标下的最优 |
| 多删误边一定提高 F1 | 还要看正确关系损失及预测数量变化 |
| 没有显著优势说明机制必然无效 | 当前数据未确认优势，也可能样本不足，不能反向宣称等效 |
| 三种子计数合计就是三倍独立语料 | 同一文档的多种子评价记录，不是更多独立原生样本 |
| 表格与算术完整就等于实验真实 | 只能证明有限内部一致性，运行真实性需要原始材料 |

## 进一步阅读前的自测

1. **为什么增强文不做完整图生成监督？** 因为部分关系未审核或被屏蔽，完整生成目标会把不可靠标签重新引入。
2. **为什么所有组件坐标都要更新？** 前面文本长度变化会移动后面只读组件，关系又引用完整坐标身份。
3. **为什么标签输运性质不能证明语义保持？** 它只证明图对象按双射完整搬运，语言是否支持标签是另一件事。
4. **为什么降低 CDCP 的 $\kappa_R$ 会允许更多低概率关系？** 单对象权重正值条件从 $q>0.5$ 变成 $q>0.25$，等价于更重视漏检代价，但事务还有其他门。
5. **为什么分数必须冻结？** 只有共同对象前后分值相同，删增差分才精确，同一效用的单调终止论证才成立。
6. **局部与全局为什么不能只比同样的预算数字？** 局部逐步分项门和累计编辑比全局终态分项门与净编辑更限制路径。
7. **为什么表 5-5b 的未入池数很小，不代表候选几乎没遗漏？** 先被终态端点缺失归类的关系不会再计入后面的未入池列。
8. **主表最终分数能证明哪些细模块有效？** 只能支持所比较整套配置；具体模块需要相应内部消融，当前多个机制仍未确认独立优势。
9. **实际 CPU 案例填补了什么，又没填补什么？** 填补真实文本与弱模型规则错误变化的解释，没有验证主生成器、评分器与闭合求解链。
10. **要把该稿用于真实成果陈述，最先补什么？** 真实目标模型和数据流程的原始输出、独立审核、评分数组与求解轨迹，并按统一身份复算结果。

能够回答这些问题，就已经掌握全篇最重要的对象定义、训练接口、推理决策和证据范围。回读原稿时可以把注意力转向具体实现及真实实验是否兑现这些规约。
