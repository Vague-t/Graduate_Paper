# 第二章统计复算材料

本包把2.6.3节落实为可运行接口。DEMO文件是刻意构造的教学输入，不是AAEC或CDCP论文结果，也不替代原稿主实验。随机数种子20261012和PCG64为本轮新增的复现设置，不声称是原稿历史运行设置。

## 文件用途

|文件|作用|
|---|---|
|recompute_statistics.py|验证配对计数，计算逐种子micro-F1、联合重采样差值、区间及Holm p|
|main_family_14.json|7组×2语料的主要比较清单；方法名需与实际计数文件映射一致|
|demo_counts.jsonl、demo_family.json|2文档×3种子×2方法的12行构造输入及1项教学比较|
|demo_validation/results.json|教学比较输出，包含每次重采样差值及输入、脚本摘要|
|demo_validation/paired_indices.json|教学比较实际使用的共同种子和源组抽样索引|
|statistics_selftest.json|9项接口检查结果|
|verify_ch02.py、boundary_qa.json|读取原生AAEC案例并验证字符身份与坐标往返|

## 计数格式

每行JSON至少包含dataset、document_id、source_group、seed、method、object_family、tp、fp、fn、status。主键为前述语料、文档、种子、方法和对象族；TP、FP、FN是非负整数。status只取ok或failed，失败使用空预测计数，金标全部记入FN。

同一文档与对象族在所有方法、种子中的TP+FN一致，文档及源组关系一致。脚本拒绝重复主键、缺失配对、金标总量变化和非空失败预测，不自动忽略这些错误。若每个主要比较方法都保存完整关系计数，当前9个方法对应AAEC 80×3×9=2160行，CDCP 150×3×9=4050行；另有组件族时应另存或按族组织。

## 运行

在本目录运行（Python环境需提供NumPy）：

```sh
python recompute_statistics.py --self-test
python recompute_statistics.py --counts demo_counts.jsonl --comparisons demo_family.json --output demo_validation --resamples 2000 --seed 20261012
```

输入主结果计数后，将counts和comparisons分别改为实际JSONL与main_family_14.json，输出到新的版本目录。主要族必须一次性提供完整14项，不能先挑选显著项再调整。

本轮教学例中A、B逐行相同，因此配对差值为0、区间为[0,0]、原始及调整p均为1。这仅检查配对零差异语义。两篇教学文档的micro-F1是95.238095…，逐文档F1平均则为50，检查程序据此确认实现先汇总计数、再计算F1。

## 计算定义与限制

种子和源组分别有放回抽样，每次所有方法共享索引；同一源组的全部文档共同进入。联合重采样先计算抽样种子的micro-F1，再平均；仅文档重采样区间固定使用全部三个原始种子。分位数采用线性插值，双侧p采用正文式（2-10），随后在完整比较族内进行Holm调整。脚本记录共同索引、随机数设置和SHA-256，允许逐次追踪。

接口检查覆盖micro汇总、零分母、同方法配对、已知Holm算例、相同输入复现、重复拒绝、缺失配对拒绝、金标总量不一致拒绝和失败计数检查。它们验证脚本定义，不验证原稿现有显著性数值，也不证明三个种子充分覆盖训练随机性。

原稿目前缺少完整主结果输入，因此Q-04仍为部分修复。后续如果构造新的test模拟计数，应明确其生成规则，重算并同步修改所有相关结果表，另建模拟版本。
