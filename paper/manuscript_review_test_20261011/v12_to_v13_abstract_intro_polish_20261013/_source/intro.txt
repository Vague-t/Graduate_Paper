第一章 绪论

[B0170] heading 2
1.1 研究背景与意义

[B0171] Body Text
论辩是人们表达观点、说明理由和回应不同意见的重要方式，广泛存在于议论文写作与公共议题讨论等语言活动中。理解这类文本，需要联系作者的主张与相应理由，并辨别不同论述之间的支持或反驳关系。面对内容分散、表达多样的文本，人工梳理论证过程需要逐一分析语句及其上下文，耗费较多时间。因此，自动识别文本中的论辩结构，是自然语言理解研究中具有实际价值的问题[1]。

[B0172] Body Text
论辩挖掘（Argument Mining，AM）旨在从自然语言文本中识别论辩组件及其相互关系，将非结构化的论述转化为可分析的结构[1]。其中，论辩组件是承担观点、理由等功能的文本片段，组件之间的关系则描述这些片段如何共同构成论证。通过确定组件在原文中的位置、判断其论辩角色并识别关系，可以得到文本对应的论辩图。在写作辅助场景中，这种结构可为分析理由是否围绕观点展开提供依据；在公共意见分析中，它有助于整理不同立场及其理由，为后续比较和人工研判提供信息。

[B0173] Body Text
以论辩标注作文语料AAEC中的essay001为例，作者提出合作有助于儿童学习人际交往技能，并从团队合作中的相处经验、沟通与妥协以及生活技能等方面说明理由。图1-1展示了其中一组支持关系：T3表示被支持的观点，T4、T5和T6分别表示支撑该观点的理由。论辩挖掘需要从原文中识别这些片段，区分观点与理由的角色，并恢复理由指向观点的连接。该例说明，文本中的论辩结构由组件及其关系共同构成，二者需要结合上下文进行判断。

[B0176] Body Text
围绕上述任务，已有研究从组件识别与关系分类出发，逐步探索对论辩结构进行联合建模的方法[2][4]。随着预训练语言模型的发展，生成式方法进一步将组件边界、组件类型和关系组织为统一输出，使从原始文本直接生成论辩结构成为一种可行的技术路线[7]。这一变化为利用上下文信息和统一处理多个子任务提供了条件，但输出形式的统一并不意味着结构判断已经可靠。训练数据能否提供有效监督，以及预测结果中的局部错误如何得到恰当修正，仍是需要研究的问题。

[B0177] Body Text
在训练数据方面，论辩结构标注需要同时确定文本片段、论辩角色及其连接，数据构建成本较高[1][2]。利用语言模型改写已有文本，可以丰富表达形式，为扩充训练样本提供途径[15]；然而，文本表达发生变化后，原有标注是否仍然成立需要检查。两段文字即使主题相同，也可能在立场、论述范围或理由强度上存在差异，从而影响组件的角色以及对其他组件的支持关系。已有槽位化增强方法通过保持语义来沿用标注[35]，但对于组件与关系相互依赖的任务，还需要进一步判断哪些监督信息能够可靠保留。

[B0178] Body Text
在预测结果方面，组件识别与关系判断之间的依赖增加了错误处理的难度。组件的边界或类型错误可能同时影响多条关系；相应地，修改一个组件后，与其相连的关系也需要重新判断。例如，图1-1中的T3与三个理由相连，若只调整T3而直接保留原有关系，修改后的图仍可能与文本含义不一致。另一方面，过多的重新生成或反复修订会增加计算开销，也可能破坏已经正确的部分。因此，如何在控制修改范围和计算成本的同时，协调处理组件与关联关系，是提升论辩结构预测可靠性需要面对的问题。

[B0179] Body Text
对上述问题开展研究，具有方法与应用两方面的意义。在方法层面，论辩挖掘同时涉及文本语义、组件角色和关系结构。考察文本改写后监督信息的保留条件，有助于明确数据增强在结构化任务中的使用边界；研究组件变化对关联关系的影响，则有助于分析局部修正与完整结构之间的联系。对这些问题的研究能够为论辩挖掘的训练与预测方法提供更具体的设计依据，也可为其他包含对象依赖的结构化抽取任务提供研究思路。

[B0180] Body Text
在应用层面，更准确的组件识别与关系恢复，有望为议论文分析、写作反馈和公共意见整理提供更可靠的结构信息。例如，写作反馈可以结合观点及其相连理由展开，意见整理也可以保留不同主张背后的理由，便于使用者检查和比较。研究数据利用效率与修正成本，还有助于评估相关方法在标注资源和计算资源受限条件下的适用性。本文据此从训练阶段的监督保持和推理阶段的结构修正两个方面展开研究，具体研究内容在1.3节介绍。

[B0181] heading 2
1.2 国内外研究现状

[B0182] Body Text
围绕论辩结构的自动识别与恢复，相关研究涉及端到端建模、训练数据构造和预测结果修正等方面。本节首先介绍端到端论辩挖掘与生成建模的发展，随后梳理关系保持数据增强和结构化预测修正方法，最后结合已有工作的特点与不足，说明本文的研究定位。

[B0183] heading 3
1.2.1 端到端论辩挖掘与生成建模

[B0184] Body Text
组件与关系的联合预测是端到端论辩挖掘的基础。Stab和Gurevych围绕说服性作文建立组件与关系分析方法[2]；Eger等将组件识别与论证结构预测纳入神经端到端学习框架[4]；Morio等通过双仿射解析和任务特定参数化支持非树状结构预测[5]。这些工作使组件识别、关系判断和结构约束能够在统一任务中研究，同时提示不同语料不能一律按树结构处理。

[B0185] Body Text
生成式方法进一步统一了多个子任务的输出接口。Kawarada等将论辩挖掘表述为文本到文本生成，本文将其作为直接生成式对照[7]。Cabessa等把组件分类、关系识别和关系分类组织为生成任务，其方法基于已有组件列表展开，评价范围与从原始文本定位跨度的设定不同[8]。AASP则以受约束的预定义动作逐步构建论辩结构，将结构信息引入自回归生成过程[9]。本文依据该工作的2025年公开预印本讨论其机制。

[B0186] Body Text
GMAM通过约束指针与重构位置编码生成组件和关系序列[47]，提供了处理输出依赖的一种紧凑方式。UniASA则将多种论辩结构任务统一为序列生成，并引入子任务分解的多视图学习[48]。前者为结构生成机制提供参考，后者有助于考察统一表示与辅助任务的作用；本文的成对学习则以同一原文及其经过审核的改写为对应单位。统一生成、辅助目标与对应约束解决的问题有所联系，其比较需要统一输入条件与完整对象评价规则，而不能仅按是否使用大模型分类。

[B0187] Body Text
结构与语义信号为生成提供了更具体的条件。DENIM使用篇章结构感知前缀辅助端到端预测[12]；Das等以关联组件间的关键短语表达概念联系[13]；FOL-AM利用一阶逻辑规则组织关系查询和多跳推理[14]。后两项工作以已分割组件为前提，适合用于比较关系语义建模思想，不能直接将分类分数视为端到端严格抽取结果。

[B0188] Body Text
组件边界仍是生成系统中的重要误差来源。Caputo等在2026年采用成对标签进行细粒度组件分割，并分析自动分割对后续分类的影响[6]。同年的ARGUS系统整合组件分割、组件分类、关系识别与分类，并连接符号求解器开展论辩框架分析[10]。结合LLM论辩挖掘综述所讨论的任务和评价差异[11]，本文重点研究可独立检验的监督保持与结构恢复机制，而非模型规模或生成式接口本身。

[B0189] heading 3
1.2.2 关系保持数据增强

[B0190] Body Text
数据增强通过改变表达扩充监督，但生成内容与原标签之间的对应需要单独检查[15]。CoDa从训练实例提取生成约束[16]，SegMix在任务相关片段上进行结构感知混合[17]。这些方法表明，增强的作用不仅取决于样本数量，也取决于生成条件和标签可靠性。

[B0191] Body Text
论辩挖掘中与本文密切相关的方法是质量导向合成QOS。该方法将上下文和组件组织为槽位化输入，在改写后恢复跨度并继承组件类型及关系标注；其方法节说明，论辩关系并未显式提供给生成模型，而依赖语义保持使原关系继续成立[35]。这一做法为局部改写提供了基础，也提出了一个需要继续检验的问题：哪些标签确实在改写后保持，哪些只能视为未知。

[B0192] Body Text
QOS与同一研究提出的多样性导向合成DOS分别提供质量和多样性的参照[35]。本文的QOS式适配继承槽位化改写思想，不等同于原论文两种方案或完整系统的复现。2026年10月公开的对抗强化学习合成研究交替优化生成器与判别器，生成新的文本—结构标注对[49]。因此，已有研究同时关注结构质量与多样性。本文研究的是保留原图监督的局部改写，其数据构造与学习目标分别在训练规模和下游抽取器受控的条件下比较。

[B0193] Body Text
关系抽取研究为这种质量控制提供了相关思路。ConsistRE以关系条件和上下文约束组织细粒度生成[38]，CovEReD通过反事实实体替换研究文档级关系预测的一致性[37]，ODDA关注低资源条件下增强样本的质量与多样性[39]。Wang等将LLM生成样本用于联合实体关系抽取，结合一致性正则化、伪标签与迭代反馈[36]。本文对后一工作的讨论限于出版方摘要和方法摘录，未核实的细节不作为排除性比较的依据。

[B0194] Body Text
增强还可能改变模型对表面线索的依赖。话语标记补全的效果因语料而异[40]，弱监督论辩挖掘也需要处理组件边界和关系噪声[18]。因此，本文同时评价标签漂移、表达多样性、接受覆盖和训练成本，并在同一批增强样本上比较不同学习目标。关系保持作为生成与审核目标，其可靠程度由因素审核和下游任务评价共同判断。

[B0195] heading 3
1.2.3 结构化预测与论辩图修正

[B0196] Body Text
结构化预测可以在生成时施加约束，也可以在生成后选择和修正候选。语法约束解码通过限制后继token控制输出形式[19]，AASP则把结构动作约束纳入生成过程[9]。这类约束保证的是已编码的规则，跨度是否准确、关系是否成立还需要依据文本与标注评价。

[B0197] Body Text
生成后修订和多候选聚合提供了另一类接口。Self-Refine利用反馈迭代修订输出[20]，自一致性通过采样多条路径聚合答案[22]。在缺乏外部反馈的推理设置中，自纠错也可能无效或降低表现[21]。论辩分析中的LLM-refine生成不同Claim、Evidence和Warrant组合，再选择分割结果[23]。上述研究支持对候选与判断过程分别分析，而不是默认更多修订必然带来收益。

[B0198] Body Text
对象与关系的联合处理也已有相关研究。Re-Cent以关系标签引导跨度对抽取，并通过关系与跨度对之间的相关性实施修正[43]。Pirozelli等的论辩重构流程提供组件合并、重写和关系检查步骤，该流程允许改写组件表述，区别于原文字面跨度抽取[44]。Xiao和Li的ARGUS研究则把LLM自解释转为抽象论辩框架，以形式语义定义最小代价修复目标[24]；它与前述同名论辩挖掘系统不是同一工作，修复目标也不同于本文的抽取对象效用。

[B0199] Body Text
本文的直接基础是ICIC 2026提出的多候选重排序与有界修正方法MCR-BR[34]。原方法已包含候选跨度替换、类型调整和关系修改。本文进一步关注组件修改后的完整依赖处理：哪些关系必须重新评价，组件与关系的修改应在什么条件下共同接受。集合动作与求解路径作为实现选择分别检验。

[B0200] Body Text
评价目标为上述设计划定了边界。以F1为目标的最优决策一般不能直接由单个对象的边际概率决定[41]，校准概率与最优F1阈值的关系也依赖特定条件[42]。概率校准用于检查置信度与经验正确率的对应[45]。本文据此区分对象概率、代价敏感效用和严格抽取F1，通过固定候选和评分的比较检验事务机制，并独立报告错误接受与计算成本。

[B0201] Body Text
综合上述研究，方法比较还需考虑语料任务表示和训练来源的差异。MT-AM利用辅助论辩语料开展多任务训练[25]；AMELIA统一19个数据集的格式，并比较单任务、多任务及模型合并策略[26]。句子级泛化研究还观察到模型对数据集相关词汇线索的依赖[27]。本文以两种原生任务检验方法的适用范围，并将附录中的历史跨域结果单独保留。多任务训练、单源零样本迁移和目标域校准具有不同数据条件，不合并为同一种泛化结果。

[B0202] Body Text
表1-1从输入条件和方法机制比较最接近的研究。已有工作为结构保持增强、多候选选择及对象修正提供了基础。本文分别研究改写前后监督对应的维护，以及组件变化后关联关系的完整重建，并为两者设置相应对照。

相对槽位化增强，本文增加的审核单位是可对应的组件与关系因素。关系审核覆盖改写集合内部、跨集合边界的合法端点组合，并包含无关系状态NONE；标签变化、原标签分歧或未审核的因素不参与相应的增强侧辅助监督与对齐，原文仍承担完整图生成监督。固定增强视图、有效因素掩码和辅助头后，成对项只改变对应因素的学习约束，不改变样本内容。表3-6分别比较可靠对应构造与QOS式适配、完整成对配置与NoPair，以区分数据构造和学习目标的作用。

[B0206] Body Text
相对已有的组件关系联合预测与MCR-BR，本文细化的是生成后修改的事务规约。组件身份改变时，失效旧关系的删除与新关系的重建共同计入一次事务；在固定候选和对象评分下，事务须满足依赖闭合、分项接受条件及预算限制，并按规定字段保留修改记录。这样，组件与关系的变化能够共同评价、共同接受并供回放核对。表4-6通过T1I1与RelationOnly的比较考察组件修改范围，通过Single与Sequential的比较考察共同接受方式；集合动作及局部、全局求解的作用另由对应比较判断。

[B0207] Body Text
相关文献涵盖结构解析、文本生成、结构感知生成、动作生成与大模型系统。本文采用Kawarada等的文本生成方法与UniASA作为外部端到端适配对照，选择依据及转换规则见附录G。GMAM、DENIM等工作用于分析结构生成机制，QOS／DOS用于说明数据构造方法，其中QOS式适配另在第三章进行比较。外部适配对照按输入、表示及代码入口的可核对程度选择，并统一接入AAEC stance、CDCP完整源集合及预测坐标的共同评价规则。其他语言和任务范围见附录A.3。

[B0209] Body Text
针对训练数据扩充中的监督保持问题，以及预测图修正中的组件关系依赖问题，本文分别从训练和推理两个阶段开展研究。训练阶段关注文本改写后可用于学习的可靠对应，推理阶段关注组件修改与关联关系重建的协调处理。两项研究的关系如图1-2所示，以下进一步说明研究问题、主要内容及其与已有工作的联系。

[B0212] Body Text
围绕上述两个阶段，本文提出以下研究问题。

[B0213] Body Text
RQ1：局部改写后，怎样识别可用于学习的组件与关系对应？在相同源文档、变体规模和更新预算下，可靠对应构造、因素级辅助监督与成对学习分别产生什么作用，其收益能否抵偿筛选、拒绝和审核成本？

[B0214] Body Text
RQ2：给定候选空间与冻结对象评分，怎样完整处理组件修改的关系依赖，并控制误改与计算成本？单对象与集合动作、局部与全局求解分别适用于什么规模和预算，哪些差异来自动作范围，哪些来自共同决策？候选空间之外的遗漏单独归因。

[B0215] Body Text
