2.1 论辩挖掘任务与结构表示

[B0237] p | heading 3 | math=0
2.1.1 论辩组件与关系

[B0238] p |  | math=0
论辩挖掘的输入是一篇未提供金标结构的文档，输出包括论辩组件及组件之间的关系。组件识别需要确定相关文字在原文中的位置，组件分类则判断这段文字承担的论辩角色。本文的端到端设定要求模型从原文完成这些预测，不使用测试集金标组件作为输入；这一设定允许生成、候选选择和预测修正等多个计算步骤。

[B0239] p |  | math=2
记固定文本版本的文档为 x，其标识为 d。文档标识同时关联语料、原生文档编号及文本版本，字符位置按照原文中的Unicode码点从0开始计数。组件的规范表示定义为

[B0240] p |  | math=1
c=(d,b,e,t),    0≤b<e≤|x|.（2-1）

[B0241] p |  | math=3
其中，[b,e) 为左闭右开的字符区间，x[b:e] 是组件的原文片段，t 为该语料的原生组件类型。相同文字在文档的不同位置出现时，对应不同组件；同一字符区间被赋予不同类型时，也对应不同的预测对象。本文将字符区间和类型共同作为严格匹配的依据。

[B0242] p |  | math=0
评价分词和模型分词是对原文的两种派生表示。评价token用于统一评价处理和跨度索引，模型子词用于构造神经网络输入；二者均通过字符偏移映射回原文。它们可以采用不同的切分方式，但不能改变组件的规范字符边界。改变分词器时，应重新建立映射，而不是重新定义金标组件。

[B0243] p |  | math=7
二元关系表示两个组件之间的有向联系，可记为 r=(ci,cj,ℓ)，其中 ci 为源组件，cj 为目标组件，ℓ 为关系标签。关系方向由提供理由或攻击的一方指向目标。文档的论辩结构记为 G=(C,R)，其中 C 为组件集合，R 为关系集合。

[B0244] p |  | math=2
部分语料允许多个组件共同支持一个目标。对此，关系表示为 h=(S,cj,ℓ)，其中 S 为非空源组件集合。源集合只在序列化时按规范键排序，其成员共同构成一个完整关系。将该关系拆成多条二元边会改变任务的计数单位和匹配条件，因此本文保留原生多前提结构；二元关系可以视为源集合大小为1的特例[3][46]。

2.1.2 字符坐标与对象身份

[B0249] p |  | math=0
规范字符坐标解决的是“评价对象究竟是哪段文字”的问题。若只以评价token的起止位置和类型定义组件，则两个具有相同token外包范围、但字符边界不同的片段可能被误认为同一对象。词中边界尤其需要保留这一差别。

[B0250] p |  | math=3
设评价token的字符区间依次为 [ai,zi)。对于组件字符区间 [b,e)，取与其相交的首、末token索引 s,u，索引从1开始。记录左右字符残差后，有

[B0251] p |  | math=1
ρL=b-as,  ρR=zu-e;    b=as+ρL,  e=zu-ρR.（2-2）

[B0252] p |  | math=2
因此，派生记录 (s,u,ρL,ρR) 可以恢复原字符区间；只有 (s,u) 则通常不能。若协议保留首尾空白，残差按有符号坐标差保存；没有可对应token的异常应单独记录，不能补造跨度。模型子词同样依据offset mapping与字符区间建立对应。由聊天模板或连续提示引入的位置需要另行补偿，不能混入原文字符坐标。

[B0253] p |  | math=0
表2-2给出AAEC原生文档essay098的T6组件。原标注止于单词responsible的最后一个字母之前，本文保留该标注事实，不自动扩展为完整单词。为说明身份区别，表中另外构造了一个扩展到完整单词的对照片段；该对照不是另一条金标。

[B0257] p |  | math=0
组件的规范键由式（2-1）的四个字段共同确定。关系键进一步包含完整端点和关系标签；多前提关系键包含规范排序后的完整源组件键集合。候选去重、评分缓存、修改记录和严格匹配均使用这一身份。T3、T4等显示编号只用于文档内部引用，重新编号不会产生新对象，也不计为一次编辑。

[B0258] p |  | math=0
组件边界或类型改变后，规范键随之变化，与该组件相连的关系也必须依据新端点重新判断。即使关系显示编号未变，也不能直接沿用旧关系的身份或评分。序列化采用统一的sources字段表示源集合，并保留AAEC stance属性；缺失端点作为异常处理，不通过补造组件或关系恢复。

[B0259] p |  | math=1
原文与增强视图属于不同文本版本。第三章的对应映射 φ 连接两个版本中的组件，用于描述槽位回填后的标注对应，不表示两侧字符键相等。改写引起字符长度变化时，所有受影响组件的位置都需要更新；哪些组件或关系可以参与学习，再由相应审核状态决定。

[B0260] p |  | math=0
结构化预测需要区分对象的定义、可搜索范围、实际输出及其评价。表2-3将后续使用的五个层次放在同一框架下，避免把“存在候选”“评分较高”和“预测正确”混为一谈。

[B0261] p | caption | math=0
表2-3 论辩结构预测的五个层次

[B0262] tbl |  | math=0

合法结构集合记为 GA，其中 A 为固定的语料协议。合法性至少要求跨度位于原文、类型和关系标签有效、端点存在；重叠、嵌套及拓扑限制则按具体语料确定。树结构或无环性不作为所有论辩文本的默认条件，不能通过删除不符合预设规则的测试标注来制造合法性。

2.2 预训练语言模型与学习方法

[B0265] p | heading 3 | math=0
2.2.1 注意力机制与自回归生成

[B0266] p |  | math=0
Transformer利用注意力机制聚合不同位置的信息，是本文所用骨干模型的基础[30][31]。注意力将查询与键的相似程度转换为权重，再对值向量进行加权。缩放点积注意力写为

[B0267] p |  | math=1
Attention(Q,K,V)=softmax(QKTdk)V.（2-3）

[B0268] p |  | math=5
其中，Q、K、V 分别为查询、键和值矩阵，dk 为键向量维度。此处的 V 是注意力计算的局部符号，与第四章的组件候选集合不同。多头注意力在不同表示子空间中计算信息关联；自回归解码还限制当前位置只能使用输入和已经生成的输出，防止使用尚未生成的输出。

[B0269] p |  | math=2
对于论辩挖掘，可以将组件位置、类型和关系序列化为输出序列 Y=(y1,…,yL)。给定原文 x，其生成概率及监督目标分别为

[B0270] p |  | math=1
Pθ(Y|x)=k=1LPθ(yk|x,y<k),（2-4）

[B0271] p |  | math=1
Lgen=-k=1LlogPθ(yk|x,y<k).（2-5）

[B0272] p |  | math=0
训练时利用金标前缀计算下一输出符号的损失，测试时则使用模型已经生成的前缀。生成式论辩挖掘将多个子任务组织到同一输出接口中[7]，但输出概率仍受序列长度、字段次序等因素影响。较高的序列概率不能直接替代对完整论辩对象的正确性判断。

[B0273] p | heading 3 | math=0
2.2.2 参数高效适配与连续提示

[B0274] p |  | math=0
预训练模型包含大量参数，针对具体任务更新全部权重会增加训练和存储成本。低秩适配LoRA在冻结基础权重的同时学习低秩增量[32]：

[B0275] p |  | math=1
W=W0+αrBA,    A∈ℝr×din,  B∈ℝdout×r.（2-6）

[B0276] p |  | math=3
其中，r 为低秩维度，α 为缩放系数。训练主要更新增量矩阵，而保留基础权重 W0。连续提示则通过可学习的提示向量表达任务条件，是另一种参数高效适配方式[33]。二者分别从权重更新和输入条件入手，可为下游任务提供可训练接口。

[B0277] p |  | math=0
本文选择Qwen3.5-9B作为主骨干[51]，在同一骨干上配置ICIC/MCR-BR基线T0、本文T1及外部适配对照。9B承担完整消融和错误分析，Qwen3.5-4B检查较小骨干下的适用性，Qwen2.5-7B-Instruct用于衔接已有方法并开展跨版本验证[53][54]。后两者共享9B增强与审核流程所得到的视图，各自配置抽取器、评分器和提案器；附录E保留原发表数值，不以更新后的数据替换历史记录。

[B0278] p | heading 3 | math=0
2.2.3 数据增强与因素一致性学习

[B0279] p |  | math=0
数据增强通过改变输入表达扩充可学习样本。语言模型能够生成与原文相关的改写，但生成文本通顺并不意味着原有标注能够全部沿用[15][35]。对于论辩挖掘，增强样本包含组件位置、类型和关系等多类监督，局部语义变化可能只影响其中一部分。因而需要把“文本是否通顺”和“某项监督是否保持”分别判断。

[B0280] p |  | math=3
一致性学习用于约束不同视图下可对应预测的分布。以同一因素的两个类别分布 p、q 为例，令 m=(p+q)/2，Jensen–Shannon散度定义为

[B0281] p |  | math=1
JS(p,q)=12KL(p‖m)+12KL(q‖m),    m=p+q2.（2-7）

[B0282] p |  | math=0
其中，KL散度衡量两个分布的差异，式（2-7）对两侧分布对称。将这一量加入学习目标，可以鼓励原文与改写在可靠对应因素上产生接近的判断。未确认的关系标签应从相应监督和一致性项中屏蔽，不能直接改标为NONE。

[B0283] p |  | math=0
分布接近只反映所约束因素的预测一致程度，并不保证两个预测都正确，也不保证生成的完整图更准确。本文因此将原文整图生成监督、因素级辅助监督和成对约束分开处理。第三章再给出影响域、对应映射、审核掩码及归一化目标，并通过固定增强数据的比较分析成对项的作用。

[B0284] p | heading 2 | math=0
2.3 候选评分与结构化决策

[B0285] p |  | math=2
一次生成可能遗漏组件或产生错误关系，多候选方法通过形成若干备选结构增加可选择范围。设完整图候选集合为 S，重排序函数为 Erank，先选择重排序得分最高的候选图，再执行共同合法化及继承的BR-O有界修正，形成完整I0的终态：

[B0286] p |  | math=1
Grank=argmaxG∈SErank(G),Gpre=LA(Grank),    G0=BR-O(Gpre).（2-8）

[B0287] p |  | math=1
这里，LA 是各方法共用的确定性合法化过程，其变更需要记录。Grank为重排序得分最高的候选图，Gpre为合法化后、尚未执行BR-O的图；BR-O按继承协议处理并完成合法性复核后，其输出记为G0。不能按继承协议形成合法G0时，记录初始化失败。合法化与BR-O均不得借助测试金标选择修改。第四章另以R_DC表示从G0开始的依赖闭合追加修正算子；I1表示包含完整I0和R_DC的推理配置，与仅表示最后一步修正算子的R_DC相区分。

[B0288] p |  | math=3
第四章在获得I0终态G0后，构建并冻结跨度集合 U、带类型组件集合 V 和关系候选集合 P，合称候选宇宙。这些有限集合共同规定修正器能够到达的范围，“完整影响域”也相对于这一范围定义。候选覆盖、评分质量和预算内搜索是三个不同环节：正确对象未进入候选时，后续求解无法将其恢复；已经进入候选，也可能因评分或搜索限制未被选择。离线Oracle分析可利用金标考察候选上界，但不能进入测试决策。

[B0289] p |  | math=0
对象评分需要与最终评价单位一致。给定金标跨度时的组件类别概率，回答的是已知片段属于哪一类；对模型预测组件的完整正确性评分，则还需要判断其字符边界是否准确。关系评分同样需要考虑全部端点、类型、方向和标签。因此，训练辅助头的输出不能直接替代推理阶段的完整对象分数。

[B0290] p |  | math=0
概率校准检查模型置信度与经验正确率是否对应[45]。例如，在样本条件相同的情况下，一组评分接近0.8的对象是否约有80%正确，是校准关注的问题。概率质量、结构合法性和最终F1分别回答不同问题：合法图可以含有错误关系，校准较好的概率也不保证任何搜索策略都能提高F1。F1相关决策还取决于对象集合与评价条件[41][42]。

[B0291] p |  | math=0
本文使用交叉拟合产生的预测候选训练推理评分器，并将拟合、校准和策略选择的数据用途分开。由于修正过程会优先选择高分提案，还需要分别检查固定候选上的评分质量和实际接受轨迹上的误改，不能仅凭总体校准指标判断修正是否可靠。

[B0292] p |  | math=0
结构化决策在有限候选中选择满足约束的对象组合。全局优化与局部搜索可以使用不同的求解方式，但公平比较需要说明候选范围、评分、可行域和预算是否一致。更大的候选空间可能提高覆盖，也可能增加评分及求解开销；搜索得到更高的内部效用，也不必然意味着严格抽取F1提高。

[B0293] p |  | math=0
本文的AAEC候选协议枚举同文档不同组件的有向对并禁止自环，不额外以跨段或组件类型配对作硬过滤。CDCP候选源集合取所选组件按原文位置排序后的连续非空区间，目标不能属于源集合。NONE表示已定义槽位中没有相应关系的候选状态，不作为输出的论辩关系。该状态与第三章“未经确认的标签”有不同含义。

[B0294] p |  | math=0

2.4 评价指标与计数原则

[B0297] p |  | math=0
评价分别对组件和完整关系计算真正例TP、假正例FP与假负例FN。精确率、召回率和F1定义为

[B0298] p |  | math=1
Precision=TPTP+FP,  Recall=TPTP+FN,  F1=2TP2TP+FP+FN.（2-9）

[B0299] p |  | math=0
组件匹配要求同一文档中的字符区间和原生类型完全一致。关系匹配进一步要求完整源集合、目标、方向和标签一致。CDCP以完整多前提关系计数，不以展开后的二元边替代。边界F1、给定金标组件的关系分类等指标可以辅助定位误差，但不能替代端到端严格关系F1。

[B0300] p |  | math=0
micro-F1先汇总对象计数，再代入式（2-9）；它与逐文档F1或各类别F1的平均值不同。本文分数采用百分制，方法间差值用百分点表示。域内细粒度Relation-F1与历史跨域无标签Link-F1分别命名，避免将不同评价对象的数值直接求差。

[B0301] p |  | math=0
预测对象与金标对象均最多匹配一次，多余重复项计入FP。若统一预处理已经去重，应同时报告原始重复率，并对所有方法使用相同规则。解析失败、超长失败或图验证失败的文档保留在评价集合中，按空预测处理，其金标对象计入FN，失败率另行报告。文档标识缺失或重复属于记录错误，不能作为可忽略样本跳过；分母为零时按预先规定记为0，并保留整数计数。

[B0302] p |  | math=0
所有结果通过语料、文档标识、训练种子和方法标识关联。跨章重复使用同一配置时，应引用同一份逐文档记录，避免训练主表、推理主表和两阶段四种配置的结果表出现不一致的计数。最终图的净变化与修正过程中逐次接受或拒绝的记录分别保存，前者不能代替后者解释过程风险。

[B0303] p |  | math=0
I0表示继承MCR-BR的完整推理配置，包括多候选生成与重排序、共同合法化和BR-O有界修正，其最终合法图记为G0。Gpre专指重排序后经共同合法化、尚未执行BR-O的图，不混入I0结果。I1表示在完整I0之后追加依赖闭合修正R_DC的整套配置，其最终图为R_DC在G0上的返回结果。四种配置中的T0I1与T1I1分别从同一训练配置对应的I0终态出发；追加调用与编辑单独记账，完整推理时延同时包含继承阶段与追加阶段。

3.1 引言

[B0332] p |  | math=0
在端到端论辩挖掘中，组件文字既承载自身的论辩角色，也为其与其他组件的关系提供依据。因此，局部改写即使保持句意相近，也可能改变支持方向、削弱跨边界理由，或使原本没有标注关系的组件组合获得新的解释。若直接将全部旧标签复制到增强文本，增加的样本可能同时引入错误监督。

[B0333] p |  | math=0
本章研究在组件位置变化和关系语义不确定的条件下，如何构造可追踪的增强视图，并将其中通过检查的监督用于训练。方法首先定义改写的关系影响域，在字符坐标上迁移全部组件；随后分别审核组件与关系，将状态改变、待定及未审核因素的掩码置零；最后在固定视图和掩码上比较无成对、组件成对与完整成对学习。

[B0334] p | Normal | math=0
这里将同一篇原文及其改写版本称为不同“视图”；可单独决定是否参与监督的判断称为“因素”，包括一个组件的类型判断，或一组完整端点之间的关系状态判断。成对学习是在原文与改写的对应因素上比较模型输出，约束通过检查的对应因素在两种表达下具有一致的预测分布。
