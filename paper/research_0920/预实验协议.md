## 目的与边界

检验两个问题：有限候选池能否覆盖真实组件；文本评分是否能在实际模型错误上识别好修改与坏修改。这是廉价诊断，不是 0918 完整算法，也不复现论文历史成绩。不用人工扰动金标准制造主评价候选。

1. 官方训练集按文本 SHA256 分组、固定 seed=920，分为约 60% 拟合、20% 校准、20% 审计。官方测试文本及标注不读取；压缩包包含测试文件不等于使用测试集。
2. 拟合部分三折交叉拟合候选，训练含 NULL 的组件评分器。审计候选只接收文本，不接收金标准。主候选池保留初始模型组件并增加最多 128 个候选，另审计 +64/+256/+512 敏感性；这些预算运行前固定，不根据审计结果挑最好者。
3. 使用稀疏词汇/边界特征线性模型，无预训练语言模型。初始模型为 BIO token 分类器；独立参数的起止边界分类器提供全篇候选，加入 ±1/±2 token 边界扰动。类型不预剪枝，跨度可恢复率并非类型分类准确率。
4. 在校准部分选择温度和单步修改接受阈值；审计集只使用冻结参数。候选修改为插入、删除、类型替换和与单个现有组件重叠的跨度替换，拒绝制造重叠的插入/替换。每篇最多接受一次，含不修改选项。评分用相对 NULL 对数比增量减固定编辑代价；真值为严格 typed component F1 的单步差分。
5. 关系补充诊断：训练并评估给定真实组件的有向关系分类器，报告正类 PR/AP、自然基率和条件 F1。CDCP 只将原生单前提关系用于此补充任务，多前提关系单独报告且排除于分类候选，不能称 CDCP 完整端到端成绩。完整原生多前提关系的候选端点可达率仍计算。
6. 分开报告各动作的好/坏/中性比例和 AUC，防止简单删除淹没难修改。整体保留每文档候选选择结果、净 F1 变化、文档级配对 bootstrap 95% 区间（1000 次）。没有多 seed 或正式测试集结论。

- CDCP: https://facultystaff.richmond.edu/~jpark/data/cdcp_acl17.zip （作者地址）。读取 `cdcp/train/` 的 txt/ann.json；已知异常 00411 保留排除记录，参见 DFKI-SLT 数据读取器说明 https://huggingface.co/datasets/DFKI-SLT/cdcp/blob/main/cdcp.py 。原生多前提关系不悄悄展开为普通边。

- AAEC 仅原始 R 行为关系，不把 Claim—MajorClaim stance 属性转为新边。原始字符跨度去除首尾空白后映射至 `\w+|[^\w\s]` token；不对无法对齐的跨度猜测边界，记录并保留在召回分母。
- 数据仅本地研究使用；不上传 GitHub，不再分发压缩包。原始许可/再分发权限未作法律审查，不为第三方语料重设许可证。

## 判断规则（研究决策建议，不是会议/学校标准）

- 候选：主预算 exact span recall ≥95%、原生关系全部端点可达率 ≥90% 才标为较强覆盖；未达标则报告预算瓶颈，不宣称否定更强候选模型。
- 修改评分：必须超过 no-edit；好/坏区分 AUC 仅辅助，关注接受修改净 F1 与按文档 bootstrap。仅删除有效、或收益区间跨零，均不能声称组件协同修正已可行。
- 关系条件分类不能替代错误端点条件下的关系重评分、组件—关系完整事务验证；本次无论结果如何均不能宣称完整第二创新已通过。
- 第一创新的数据增强不在此次 CPU 预实验中实现；必须另外与 QOS/DOS、匹配预算随机中心和关系条件消融对照。
