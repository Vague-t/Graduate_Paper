## 第二章 任务表示与方法基础

### 2.1 论辩组件、二元关系与原生超边

设输入文档在固定评价分词器下表示为$D=(x_1,\ldots,x_n)$。组件定义为$c=(s,e,t)$，其中$1\leq s\leq e\leq n$，跨度采用从1开始的闭区间，$t$为语料规定的类型。实现同时保存原文字符坐标与评价token坐标，并检查往返一致。评价token与模型子词不是同一对象；改变评价分词器时不能复用旧坐标。

二元关系记为$r=(c_i,c_j,\ell)$，包含完整源、目标组件和关系标签，方向由提供理由或攻击的一方指向目标。预测结构写为$G=(C,R)$。“端到端”指从原始文本评价组件和关系，不提供测试金标组件，并不要求整个系统仅调用一次模型。

CDCP的多前提关系保留为$h=(S,c_j,\ell)$，其中$S$为非空源组件集合，$c_j$为目标。源集合的顺序规范化，但不拆成若干独立二元边。超边匹配要求源集合中全部组件、目标及标签同时正确；漏掉一个源成员不是同一完整关系。二元图是源集合大小为1的特例。本文用$R$统称关系对象，但实现必须保留其实际元数[3]<!--ref:park2018--><!--anchor:section:3-->[54]<!--ref:niculae2017--><!--anchor:section:4-->。

表2-1 域内任务与评价边界

|语料|组件类型|关系对象|额外边界|
|:---|:---|:---|:---|
|AAEC|MajorClaim、Claim、Premise|Support、Attack二元关系|Claim对MajorClaim的stance单列，不转换为普通关系|
|CDCP|Fact、Testimony、Value、Policy、Reference|Reason、Evidence原生超边|多前提不静默展开；类型不归并为Claim/Premise|

上述边界依据语料与联合预测研究定义[2]<!--ref:stab2017--><!--anchor:section:3-->[3]<!--ref:park2018--><!--anchor:section:3-->[54]<!--ref:niculae2017--><!--anchor:section:4-->。CDCP中的结论角色用于第三章选择增强中心，不改变原生组件标签；第五章跨语料标签归约是单独协议，不能反向改变域内金标。

### 2.2 合法结构与语义身份

相对于固定语料协议$\mathcal A$，以$\mathcal G_{\mathcal A}$表示合法结构集合。必要检查包括跨度位于原文、类型合法、关系端点存在、关系标签合法，以及语料确实要求的重叠、方向和拓扑规则。不默认所有论辩图都必须为树或有向无环图，也不为满足解码约束删除不符合假设的测试金标。若语料包含嵌套或多前提结构，应在协议中显式处理。

组件的语义身份由文档、规范坐标和类型共同确定，关系身份由完整端点及标签确定，超边另包含规范排序后的完整源集合。JSON编号仅用于序列化。编号重排不产生新组件，不计作编辑，也不触发重新打分；坐标或类型改变则是不同对象，不能复用旧端点的关系证据。

本版候选协议统一采用文档级输入。AAEC枚举同文档不同组件的有向对，禁止自环，但不额外施加跨段或组件类型配对的硬掩码；没有标注边的候选状态为NONE，不能由stance补造边。CDCP的候选源为所选组件按位置排列后的连续非空区间，目标不能属于源集合；关系标签为Reason或Evidence，其余状态为NONE。主配置对同一端点槽位采用单一关系状态，若数据审计发现并存标签，则使用显式合法标签组合，不丢弃其中一项。组件重叠、嵌套及其他语料特定限制必须由数据审计固定为协议清单；发现反例时调整协议，而不是删除金标。无环性只作为经语料验证后的可选硬约束，不作为跨语料默认条件。

以下为人工构造示例，token序列为“Libraries / should / stay / open / longer / . / Students / need / study / space / .”。它只说明坐标和引用，不作为效果证据。

```json
{
  "components": [
    {"id": 1, "type": "Claim", "span": [1, 5]},
    {"id": 2, "type": "Premise", "span": [7, 10]}
  ],
  "relations": [
    {"sources": [2], "target": 1, "type": "Support"}
  ]
}
```

统一使用sources列表可容纳超边，但不能据此认为旧二元关系模型已经支持多前提。CDCP的编码、候选构造、评分训练、优化器和评价器必须同时实现超边语义。字段顺序固定为ID、type、span等已声明顺序；第三章类型门控只能使用已经输出的前缀，不能读取尚未生成的标签。

### 2.3 生成建模与参数高效适配

对序列化输出$Y=(y_1,\ldots,y_L)$，自回归生成定义为：

$$P_\theta(Y\mid D)=\prod_{t=1}^{L}P_\theta(y_t\mid D,y_{<t}).$$

Transformer以注意力聚合上下文[30]<!--ref:vaswani2017--><!--anchor:section:Abstract-->。本文继承的参考骨干为Qwen2.5-7B-Instruct，正式实验仍须绑定权重revision、分词器、软件及硬件，模型系列报告不能替代实际运行记录[31]<!--ref:qwen2024--><!--anchor:section:Abstract-->。生成概率受长度和字段顺序影响，高概率不意味着图中关系成立。

LoRA在冻结权重上引入低秩更新[32]<!--ref:hu2021--><!--anchor:section:Abstract-->：

$$W=W_0+\frac{\alpha}{r}BA,\quad A\in\mathbb R^{r\times d_{in}},\quad B\in\mathbb R^{d_{out}\times r}.$$

其中$r$是秩，$\alpha$是缩放系数。结论条件门控是前期研究施加于专项分支的任务机制，不是重新提出LoRA。连续提示利用可学习向量表达任务条件，其基础来自提示调优研究[33]<!--ref:lester2021--><!--anchor:section:Abstract-->。本论文继承这些机制，并通过第三章的监督接口深化其学习目标，而不将通用参数高效方法计为本文创新。

### 2.4 候选空间、评分与搜索

多候选选择从已生成的完整图中确定初始状态：

$$G_{\mathrm{rank}}=\arg\max_{G\in\mathcal S}E_{\mathrm{rank}}(G),\qquad G_0=L_{\mathcal A}(G_{\mathrm{rank}}).$$

其中$L_{\mathcal A}$为各方法共用的确定性合法化过程，其规则与变更单独记录；无法得到合法状态时显式失败，不进入后续修正。因而原始重排序胜者与合法初始图不必相同。

候选池是否包含较好结构、评分器是否识别该结构、搜索能否找到更好的可达状态，分别对应覆盖、判断和求解能力。增加候选数只能可能扩大覆盖，不能自动提高后两者。Candidate Oracle仅在离线分析中使用金标度量当前候选空间，不参与实际测试决策。

第四章在初始选择后另外固定跨度候选宇宙$U$、带类型组件宇宙$\mathcal V$和关系候选宇宙$P$，并在其上计算完整对象正确性分数。影响域“完整”均相对于显式声明的有限因素宇宙，不意味着枚举任意长度文本跨度或所有非空组件子集。未进入宇宙的正确对象对当前修正器不可达，需要报告覆盖上界。

确定性合法性、模型语义判断和统计校准不能互换。合法性检查只保证遵守编码规则；评分器的概率含义需要真实预测负例和独立校准材料；不同模型参数也不能保证生成器与评分器的误差统计独立。搜索反复选择高分对象还可能放大评分误差，因此须评价最终接受轨迹，而不只报告随机样本上的校准分数。

### 2.5 严格评价与可比性

对组件或完整关系对象，分别汇总$TP$、$FP$、$FN$，定义：

$$P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad F_1=\frac{2TP}{2TP+FP+FN}.$$

新实验主指标采用精确组件micro-F1和严格关系micro-F1。前者要求跨度与类型完全匹配；后者还要求全部端点跨度、类型、方向和关系标签正确。CDCP超边以整个源集合计数，不把展开后的边数作为原生关系数。另报告边界F1及给定金标组件的关系分类诊断，但它们不替代主指标。域内细粒度Relation-F1与跨域无标签Link-F1分开命名和展示。

每个预测语义对象最多匹配一次金标；重复输出的多余项计FP。图归一化若预先去重，则同时报告原始重复率，并对全部方法使用相同规则。解析、超长或图验证失败不能删除文档；该文档的金标对象仍进入FN，失败率另报。数据ID缺失或重复须报错。集合分母为零时采用预先固定的零值约定，并保留原始计数。

micro-F1先汇总对象再计算，不等于分类别F1均值或逐文档F1均值。F1采用百分制，差值称“F1点”。跨种子报告均值及样本标准差；文档级置信区间在每次重采样后重新汇总计数，重复文本按组重采样。旧表的“±”在缺少原始统计记录时保留原符号，不追认成某一种统计量。

### 2.6 两个阶段的闭环边界

训练阶段闭环为“指定改写槽位—全文回填—影响域检查—接受或拒绝—成对学习”；推理阶段闭环为“提出集合替换—重建全部依赖—整体评分—提交或回退”。这里的闭环指每个阶段内部具有明确验证和失败出口，不是将推理结果重新作为训练金标。

```flow
训练金标 → 关系感知增强与成对监督 → 训练后生成器
原始文本 → 多候选完整图 → MCR初始图
全文跨度提议 → 固定候选宇宙 → 集合替换与依赖闭合
完整对象评分 → 整体接受或回退 → 最终图及修正记录
```

第三章辅助头在训练金标跨度上学习因素标签，第四章评分器在交叉拟合预测上判断完整对象是否正确。二者的目标和负例不同，不直接共用概率。训练改进在推理策略固定时评价，推理改进在同一生成检查点及候选宇宙内评价；跨训练检查点不强迫使用完全相同的候选，因为候选质量本身属于训练效果。

### 2.7 本章小结

本章以完整语义对象统一组件、二元关系及多前提超边，明确候选覆盖、评分可靠性和搜索能力的区分。严格评价与语料特定约束为后续两项方法提供共同接口，也限定了形式性质和实验结果能够支持的结论范围。
