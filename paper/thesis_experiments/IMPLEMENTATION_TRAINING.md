# 第三章训练与增强实现说明

本文件对应当前论文 v6 的第三章；实现位于 `argrepair/modeling.py`、`training.py`、`augmentation.py`。这是新增实验程序的工程规约，既有论文模拟表格不会自动变成该程序的实验结果。模型有效性与方法增益需要服务器上的真实训练和独立评价。

## 模型、参数和输入

- `ExtractionModel(ModelConfig(...))` 支持真实 PyTorch 小型随机因果 Transformer（`backend=tiny`）与 Hugging Face Qwen（`backend=hf`）。Tiny 仅验证代码、梯度与保存加载，不是预训练模型成绩。
- 基础模型权重全部冻结；每层 attention 的 q/k/v/o 投影都增加全局和结论专项两支 LoRA，默认每支 rank 16、alpha 32、dropout 0.05。组件头、关系头、句子头和四个连续提示向量可训练。
- 生成格式严格按组件 `id,type,span` 排序；`span` 为 Unicode 字符半开区间。存储训练集仍用共享 schema 的 `start,end,type`。`parse_generated_graph` 执行 JSON、类型、跨度、完整端点和图合法性检查，不猜测坐标或删除无效边。
- 结论门控只从当前位置之前已提供的生成前缀计算。AAEC 的 Claim/MajorClaim，CDCP 的 policy/value 类型字符串闭合后才开启；该组件对象闭合后关闭。输入、未闭合类型、关系区域均为零。不会通过教师强制的后续标签预开门控。
- 线索使用不区分大小写的词边界匹配：therefore、thus、in conclusion、consequently、hence、to conclude。命中时在完整聊天模板前增加四个提示向量，原文字符坐标不变。
- 组件/关系/句子辅助路径只调用输入全文与任务指令。原文和增强文都不把金标图、待预测类型或关系状态输入骨干。跨度池化属于下游监督定位，组件头拼接全文输入最后隐藏状态，关系头使用完整源集合均值、目标、全文末表示及七项无标签几何特征。
- 源组元数是原始计数；六项位置特征取由字符跨度相交到的`\w+|[^\w\s]` 评价 token 的起止位置并按全文 token 数归一化。与 native 字符身份不同，不修改金标跨度。若论文最终另指定评价 tokenizer，应同步替换该特征函数并登记版本。

## 真实损失与消融

| 配置 | 原文生成与句子 BCE | 原文辅助头 | 增强可靠头 | 组件双侧 JS | 关系双侧 JS |
|---|---|---|---|---|---|
| T0 | 是 | 否 | 否 | 否 | 否 |
| Heads | 是 | 是 | 否 | 否 | 否 |
| NoPair | 是 | 是 | 是 | 否 | 否 |
| CompPair | 是 | 是 | 是 | 是 | 否 |
| T1 | 是 | 是 | 是 | 是 | 是 |

完整图生成仅使用原文，损失覆盖答案和 EOS，不覆盖输入或连续提示。句子按句末标点、换行及文档结尾划分；与结论类金标跨度相交时标 1，默认系数 0.5。

辅助头监督在每个视图内按组件平均；关系按正关系/NONE 两类的非空组先组内平均再组间平均。原文与 `m` 个接受视图的头监督总和除以 `1+m`。JS 不 detach 任一侧；组件对齐仅覆盖改写组件及受影响正关系连接的只读端点，并与可靠组件掩码相交；NONE 不扩展组件对齐集合。关系 JS 同样进行非空组归一化，再按该源的接受视图数平均。无可靠关系时该项为零。

原文语义关系头与增强语义头都排除联合源真子集的 semantic unknown；原文整图生成仍保留完整超边。semantic unknown 与已定义槽位中无标注边的 NONE 不同。

默认系数：head supervision 1.0、component JS 0.5、relation JS 0.5。`train` 每次只处理一篇源文档及其视图并反向传播，`microbatch_sources × accumulation` 决定有效更新源数；末批除以实际源数。实际 optimizer、scheduler、训练日志、模型配置、checkpoint 与源文档摘要保存至输出目录。

## 增强、审核和资源边界

1. 固定种子 17，以语料、文档 ID、规范组件序号和 center 字符串进行哈希选中心，优先 Claim/MajorClaim 或 policy/value。包括所有指向中心的完整源成员，不递归、不裁剪长金标超边。
2. `build_generation_payload` 向生成方提供全文、所有改写槽位/只读端点及类型、完整正关系、语义未知例外、确定性有限宇宙和 NONE 补集定义，可无损恢复完整影响域。该含标签条件不进入盲审请求或下游提取器。生成方只能返回固定组件槽位的替换文本。`transport` 按字符区间回填，更新所有组件（包括只读组件）以及每条超边全部端点，并保留、输运 Stance 等原生属性的组件坐标绑定；当前不训练额外 Stance 预测任务。空替换、重叠、坐标往返失效、端点输运失效均拒绝。长文本不静默截断。
3. AAEC 因素宇宙包括所有有向非自环组件对；CDCP 包括所选组件顺序中连续、至多三源的区间与所有完整金标槽位。超过三源的金标不裁剪。超过因素资源上限整体报错。
4. 已知联合源同目标的无独立正标注非空真子集标为 semantic unknown；显式正标注优先。未知因素不进入可审核域，内部/边界仅相对于改写集合定义。
5. 审核器是调用方显式提供的 callable，接收 `component_type`、`component_meaning`、`relation_state` 请求。类型/关系请求只含全文、无标签跨度、原生允许类别；原文和增强文分别分类，取得输出之后程序才比较金标。meaning 请求提供原/新全文及两个无标签跨度，以检查否定、模态、指代和含义保持。模型异常或无效回答归 UNKNOWN 并保留原始响应。
6. 任一组件含义变化或待定（包括只读组件）均拒绝整个视图；改写组件类型不一致也拒绝。只读组件类型不确定则掩码为零，且所有只读组件也审核，可靠关系必须所有端点可靠。默认因素模式核查全部受影响正关系及固定哈希抽样的内部/边界 NONE 各至多四项；若正关系不能全部覆盖，则本视图关系掩码全部为零，但组件仍可参与训练。未审核因素不当作 NONE。
7. FullFilter 必须审核完整声明影响域；预算不够则跳过，任何因素失败/待定则拒绝。`max_relation_reviews` 表示因素数，每个因素需要原/新两个调用。每次调用与拒绝原因进入审计记录。
8. 上层 CLI 负责最多四次尝试、两个接受变体、生成/审核模型固定、训练源分组、调用成本和 JSONL 归档。增强与损失入口主动拒绝非训练划分。

`review_view` 的返回对象有 `to_dict/from_dict`，保存对应映射、掩码、改写集合、组件对齐集合、全部因素、原始审核请求/输出和源/增强摘要。审核不是无误的人工金标准；其误差需要独立人工抽查。

## 单卡 24GB 与内存实现

服务器建议先以 Qwen2.5-0.5B/1.5B 或更小长度验证，再运行 Qwen2.5-7B 的 NF4 双重量化、bf16 计算、gradient checkpointing、单源微批与 32 次源累积。默认不承诺 24GB 必然容纳论文最长输入；报告实际峰值显存及上下文失败，2048 smoke 与 8192 paper 配置须分开。

HF 模式可用 `four_bit=True`，要求 CUDA 和 bitsandbytes；CPU 不会伪装量化加载。输入辅助路径绕过无用的词表投影；原文生成交叉熵按 128 个答案 token 分块并 checkpoint 大词表投影；自回归推理使用 KV cache。层 checkpoint 在调用时捕获对应前向的 gate，防止原/增强多次前向后反算使用了最后一次门控。

模型仅调用可信 Hugging Face 架构，不启用远程自定义代码。保存记录请求 revision 和实际 resolved revision。`from_adapter` 按原配置加载基础模型，再检查全部可训练参数均存在；Tiny checkpoint 还保存随机基础权重，避免随机种子环境变化破坏复现。HF checkpoint 仅保存适配器/头，服务器仍需同一基础模型。

当前 `train` 保存 optimizer 状态供审计和续训实现接入，但不声称提供精确断点续训 CLI；重新运行会从指定 adapter 开始新优化器。评价推理不会使用训练语义辅助头的概率充当第四章完整对象正确率，独立对象评分模型由第二阶段模块提供。
