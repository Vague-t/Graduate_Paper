# 摘要、结论与自然表达：跨两篇材料的润色建议

版本：2026-10-13，已处理structure组交叉意见；来源抽查范围与处理见本目录《交叉意见处理.md》，最终跨组规范由主代理汇总。

## 1. 目标与依据

目标是让中文计算机硕士论文更像作者在向同行解释研究：直接、具体、有层次，同时保持必要的证据界限。不是弱化学术准确性，也不是规避AI检测。

主要依据为《现代汉语与文言文风格的迁移方法研究》完整的摘要、方法、实验解释和总结展望；《毕设论文0405》只提供已写完整的方法段和重复/缺失反例。来源页码与哈希详见同目录的[style_transfer规范.md](/Users/channtang/Downloads/paper/writing_style_research_20261013/agents/prose/style_transfer规范.md)及[prior_0405规范.md](/Users/channtang/Downloads/paper/writing_style_research_20261013/agents/prose/prior_0405规范.md)。下文ST、M编号对应两文件的证据表。

这是有限样本提炼的建议，不是学校官方规范或已验证的通过标准；学校模板、学术事实与用户明确要求优先。参考文章不一定是用户本人写作，不应将这些特征称为“用户个人文风”。

## 2. 摘要：先让读者知道做了什么

### 信息职责

摘要需要让读者理解研究对象、关键困难、主要办法和代表性结果。对于两项工作，应能看出它们各自回答什么问题，以及二者是什么关系。背景只保留支撑研究问题的内容，不必从整个领域的发展史开始。

可参考ST-01、ST-02的“问题与工作对应”，但不固定段数或句数。方法名后应接可理解的技术动作，例如“利用已有标注生成局部改写，并只对通过审核的区域施加一致性约束”，比只报多个模块全称更有用。首次出现的方法简称在必要时解释，不让摘要变成简称清单。

### 数字怎样写

- 选择能回答核心问题的结果，不把整张主表搬进摘要。
- 同时交代数据集、指标、比较对象；提升幅度应区分百分点与相对百分比。
- 主结果来自合成数据、受控模拟或诊断性实验时，摘要必须保留这一性质，不能只在附录声明。
- 未显著的结果不写成“显著提升”；个别指标更优不写成“全面优于”。结果统计和主张应保持同一口径。
- 不为满足摘要格式添加不存在的实验数字。M-01的结果缺失是未完成状态，不是可以继承的风格。

## 3. 段落：从具体问题推进，不让抽象名词替代解释

先判断这一段主要是定义、动机、操作、发现、解释还是限制，再围绕这一任务整理。自然感来自信息持续向前，而非每段都以“本节首先……”开头、以“提供有力支撑”结尾。

| 场景 | 更有效的组织 | 来源依据 |
|---|---|---|
| 引入陌生任务 | 一个简短例子 → 任务差异 → 本文关注的问题 | ST-03、ST-05 |
| 解释方法模块 | 输入与困难 → 操作 → 输出及用途 | ST-06、M-07—M-09 |
| 引入公式 | 先说它计算/约束什么 → 给公式 → 解释新增符号或关键分支 | M-07、M-12、M-15 |
| 承接下一方法章 | 前章解决了什么 → 研究场景有什么变化或哪个问题还在 → 本章研究什么 | ST-11、M-11 |
| 分析实验 | 最重要发现 → 代表性证据 → 有依据的解释 → 必要边界 | ST-08—ST-10、ST-13 |

这些是可选择的信息组织方式，不是每段必须逐格填满的模板。只有内容确有分组或顺序时才使用“首先、其次、最后”；不把连接词当黑名单，也不为了多样性机械换词。

## 4. 结果段：解释表格，不朗读表格

优先回答研究问题。例如，一张表同时有精确率、召回率和F1，正文可先解释改进主要来自召回还是误删减少，再选择一组关键数值。不要按模型顺序把每格数字改写成句子。

取舍应直说。ST-10和ST-13都保留了局部反向结果：某个组件改善部分指标，却损害另一些指标或不适合小模型。这类说明不削弱文本的成熟度；把所有结果包装为优势，反而让分析失去辨别力。

把观察与解释分开：

- “去掉该模块后召回率下降”是结果表支持的观察。
- “这可能与候选覆盖不足有关”是解释，若没有直接实验就保留“可能”。
- “因此该模块恢复了缺失候选”属于更强机制结论，需要候选统计或案例等对应证据。

不需要在每句话后附上“仅在本条件下成立”。可以在实验设置或小节开头集中说明共同范围；当比较口径发生变化、材料是合成的、结果未显著或机制仍属推测时，在相关结论处补足最短必要限定。正文局部句子被单独阅读也不能造成性质误解。

## 5. 案例：让读者看见问题怎样发生

根据ST-14，案例最好并列相同输入、参考或标注、基线输出与方法输出，并清楚标识具体错误。案例分析不必重复全部原文，只需解释与本节主张相关的变化。

动机案例说明“为什么现有方法会遇到问题”；结果案例说明“本文在这个例子中改变了什么”。二者职责不同。教学例、手工构造例、合成例和真实模型输出须明确区分。总体指标不能默认为该案例得分，单个案例也不能证明总体收益。

## 6. 小结、全文总结与展望：避免三处重复摘要

- **章末小结**：回收本章解决的问题、主要设计及最重要发现；若有影响主张的限制，保留一句。不要逐小节报目录。
- **全文总结**：把几项工作合起来说明研究完成了什么，两者是并列、互补、场景扩展还是递进。可以提核心数字，但没有必要再次逐表复述。依据ST-15。
- **局限与展望**：写具体限制怎样影响结果、下一步可以怎样检验或改进。ST-16从反馈延迟、词典依赖、未见风格与评估偏差展开，比泛泛提出“更多数据、更大模型”更有内容。
- 改变核心结果解释的限制必须在结果附近出现，不能全放到最后；跨章节的资源、数据和适用范围问题可集中在总结或专门局限节。
- “未来尝试”不能表述为已经具备的能力；“仍待验证”不能改成“进一步证明”。M-16中的空结论不进入正向写法样本。

## 7. 必须保留与可以压缩的内容

| 必须保留 | 可以压缩的重复表达 |
|---|---|
| 实验是真实执行、合成模拟、教学例还是计划 | 同一范围在连续句子中反复声明，且没有新增条件 |
| 数据集、基线、指标和提升口径 | 表格中已完整呈现的每个数字逐格复述 |
| 未显著、负向结果和重要成本/代价 | “需要强调”“值得指出”后面并没有新增重要信息 |
| 推测机制与直接验证之间的差别 | 相邻段重复同一方法全称、贡献判断和流程总览 |
| 训练/测试可用信息、关键假设与不可用情形 | 不影响理解的“系统性、全面性、有效性”多重修饰 |
| 复现所必需的参数、边界和接口 | 已有公式与伪代码后的逐字翻译 |

判定标准是删除后会不会改变事实、条件、证据性质或读者理解，不是某个词是否“像大模型”。

## 8. 原创示范：仅示范表达，不是来源原文或已完成实验

以下均为本次新写的教学示例，不引用原论文措辞，不代表用户论文的真实结果。涉及效果的句子只有在原稿证据支持时才能使用。

### 示例1：把概念堆叠改成设计动作

较绕：为缓解由局部语义变化所引发的结构监督不一致性问题，本文构建了面向有效监督边界识别的区域级可信掩码机制。

建议：局部改写可能改变组件之间的关系。为避免沿用失效标注，本文只保留审核通过区域的监督信号，其余区域不参与一致性训练。

说明：保留了改写、失效标注、审核范围和训练动作；删掉的只是抽象名词包装。若实际审核或掩码并非这一范围，应按真实实现改写。

### 示例2：保留“合成”和“未显著”，不写成长串免责

较绕：需要强调的是，本节所呈现的实验结果仅来自当前受控合成场景，因而不能据此推断真实模型条件下具有普遍有效性；此外，尽管观察到正向数值变化，其统计显著性尚未得到充分支持。

建议：在该合成场景中，方法的平均F1有所提高，但差异未达到统计显著；真实模型上的效果仍待验证。

说明：合成材料性质、数值方向、统计状态和外推边界都保留了。只有检验确实完成且结论未显著时才能用“未达到统计显著”；若根本没有做检验，应写“尚未进行显著性检验”。

### 示例3：从复述排名转为解释取舍

较绕：由表可知，完整模型在多个指标上均表现出较好的性能，充分验证了所提方法的有效性与优越性。

建议：完整模型的F1高于基线，改进主要来自召回率增加，精确率则略有下降。这说明新增候选找回了部分遗漏关系，也带来了额外误报。

说明：后一句机制解释只有在候选来源和错误统计支持时使用；仅有主表时可改为“这一结果呈现出召回与误报之间的取舍”，不要补造因果。

### 示例4：展望写成能继续研究的问题

较绕：未来将进一步结合更先进的大语言模型与更多数据，全面提升模型的泛化能力和鲁棒性。

建议：当前实验只覆盖两类文本，尚不清楚跨领域时的效果是否保持。后续可在新领域上固定现有配置测试，区分模型迁移能力与重新调参带来的收益。

说明：以明确限制引出可检验问题；“只覆盖两类文本”是示例假设，不能直接粘贴进其他稿件。

## 9. 给后续skill的执行建议

1. 确认待润色章节的职责、目标读者及已锁定事实；信息不足时标记，不自动补实验。
2. 先检查段落推进和近距离重复，再改句子。不要一上来同义词替换。
3. 优先把动作、对象和逻辑关系说清，术语只在确有技术意义时保留；机制与因果只按已有证据表述，不能为让叙述顺畅而补造原因。
4. 保留来源状态、范围、未显著结果和重要反例；把重复限定合并到最合适位置。
5. 在本次实际改动的段落及必要的相邻引用范围内，对照原稿复核数字、比较对象、符号、模型名与主张强度。纯语言润色不默认扩成全文科研审计；发现矛盾时标记冲突，不擅自替作者选一版事实。
6. 输出修订段落和少量关键改动说明。若任务是纯润色，不顺手增加创新点、实验、图表或结论，也不因语言调整而要求重新开展与本次改动无关的实验核验。

验收问题：同行能否更快明白“问题是什么、做了哪一步、证据到哪里为止”？不要以固定句长、固定段数、术语密度、某些词出现次数或AI检测分数作为验收标准。
