# 0918 方法设计：文本证据约束的组件—关系事务式协同修正

版本：2026-09-18，研究设计 v1.0。

状态：**可实施的研究方案，不是已经完成的新实验结论。** 本文不替换 `report_0915_v1`，不把 BR-O/BR-C 历史结果迁移到新方法。作者关于原实验已完成的说明仍成立；本方案改变了动作、评分器和接受规则，效果需用对应新配置验证。

配套文件：[文献证据与检索记录](research_0918/文献证据与检索记录.md)、[主张边界](research_0918/claim_intent.md)、[审查与实施路线](research_0918/审查与实施路线.md)。构造脚本的 16 项检查已经运行通过，仅检查设计机制和限制，不代表正式模型效果。

## 一、核心判断：可行，但创新必须落在“如何改对”而非“能改什么”

建议继续推进组件—关系协同修正，并把 BR-C 保留为重要对照。不是简单恢复 BR-O 的类型修改，也不是在 BR-C 前面再接一个组件改写器。

推荐研究问题为：

> 在端到端论辩挖掘中，当组件的存在性、跨度或类型发生变化时，如何共同更新受影响的关系，并在统一证据标准下接受或拒绝整次修改，从而取得可验证的净修复收益？

推荐方法的一句话解释：

> 先从原文准备有限的组件备选；每次提出一个组件修改，把所有受影响的关系一起重新判断，只有整个修改包通过原文证据、结构约束和统一评分才提交，否则完整回退。

“事务”只是指“一起提交或一起撤回的修改包”，不是数据库系统创新。“协同”是组件方案依据关系重建后的整体得分竞争，关系方案又依赖修改后的组件；不是仅把两个模型顺序串联。

### 1.1 文献如何改变了本次设计

- 联合优化组件类型与关系已有长期基础，不能写成首次提出。[Stab & Gurevych, 2017](https://aclanthology.org/J17-3005/) <!--ref:stab2017--><!--anchor:section:5-->
- 近期工作已经同时关注边界改进和关系去噪，因此“两个子任务都改善”不是足够的区别。[Sun et al., 2026](https://aclanthology.org/2026.fever-1.1/) <!--ref:sun2026weak--><!--anchor:section:3-->
- 置信度门控也已有近邻；其中部分研究是在金标准边界上判断关系，不能与本文端到端精确匹配直接比较。[Bąba & Chudziak, 2026](https://arxiv.org/html/2606.16047v1) <!--ref:baba2026relations--><!--anchor:section:3.1-->
- 形式论辩中的最小成本修复已经出现，本文不使用“首次最小修改修复”定位。[Xiao & Li, 2026](https://proceedings.mlr.press/v337/xiao26a.html) <!--ref:xiao2026argus--><!--anchor:section:abstract-->

因此，本轮更有价值的切口是：**可变组件条件下的评分可比性、端点证据失效处理、整体事务接受，以及它们是否确实减少净误改。**这四项共同服务于一个贡献，不应拆成四个创新点。现阶段对创新性的评价是“有研究潜力，但仍可能被普通结构化解码解释”，不是已确立的高创新。

### 1.2 三条路线的取舍

|路线|能解决什么|主要问题|建议|
|---|---|---|---|
|BR-C 关系修正|组件固定时改善边|组件遗漏、边界和类型错误不可恢复|保留为风险较小的参照和降级路径|
|直接组件修正 → 全部关系重预测|可改变组件，并重新建立关系|难区分组件、评分器、额外预算和搜索方式的贡献|必须实现的强简单基线|
|固定证据空间＋依赖闭合事务|同时修改组件与关联关系，并提供一致的接受和回退规则|候选召回、验证器准确性、实现和成本均需检验|推荐研究主线，不预先宣布优胜|

另设同评分器的全局 ILP/受限联合解码作为“最强替代解释”对照。如果它同样准确且不更昂贵，就没有理由把事务搜索包装为更优的核心算法。

## 二、从现有版本出发：哪些能复用，哪些必须重做

本轮核查了本地 `argument_mining_0914/am/repair.py`、`schema.py`、`backend.py`、`metrics.py` 及 0915-v1 第四章。

|当前实现事实|对新方案的影响|
|---|---|
|BR-C 固定组件，覆盖锚点由初始组件确定|不能仅关闭 `fix_components` 就称为联合修正；一旦组件可变，旧保护不再解决评分对象变化|
|BR-O 的 Replace 保留 ID，主要替换重叠跨度或类型|没有一般性的漏组件补回能力；需显式 Insert/Delete 及原文候选来源|
|评分由覆盖、边验证均值和合法性加权构成|可变组件下继续使用动态分母会重现漏洞；新主方法必须换接受目标|
|边验证接受当前整图作为上下文，输出 0/1|不同图中同一边的证据条件可能不同；不适合作为本方案的冻结概率表|
|新增边按 `(source_id,target_id,type)` 判断|组件内容变了而 ID 不变时会漏掉重核验；必须使用语义端点身份|
|精确关系评价默认包含两端跨度、类型和关系类型|端点变化本身就能改变关系 TP；必须分开报告端点修复与边判断收益|
|现有项目是后来建立的参考实现|其可复用代码不等于已复现作者原始正式实验；新 run 必须有独立身份|

复用数据坐标、图解析、候选缓存、预算日志和现有精确匹配指标。新建评分器、候选空间、事务、局部求解及轨迹审计模块；不在旧版原地覆盖算法身份。

## 三、任务定义与适用范围

输入文档为固定评价 token 序列 \(x=(x_1,\ldots,x_n)\)，组件为 \(c=(s,e,t)\)，坐标使用项目现有的 **1-based 闭区间**。图为 \(G=(C,R)\)，关系为有向、带标签的组件对。

AAEC/CDCP 分开训练或使用明确的协议映射。标签、MajorClaim 关系处理、多前提关系表示及有无环约束均写入 `schema_version`。不因为当前代码默认检查有向无环，就断言所有语料的金标准都必须满足该约束。

下文采用“一个有向组件对至多一个关系标签”的二元边设定。若导入数据允许同对多标签，需要改为 multi-hot 状态；若存在必须联合解释的多前提结构，需要显式采用超边或说明展开协议及语义损失。不能为了适配本设计静默丢弃或拆开金标。协议审计是正式实现前的必要条件。

本方案修复的是“原文里存在但抽取有误的显式组件和关系”。**不改写原始文档，不生成原文没有的隐含前提，不把论证是否真实、充分或合理当作抽取标签。**例如，文章确实用一个错误理由支持观点，挖掘系统仍应忠实抽取该支持关系；不能因世界知识认为理由不成立便删除关系。

首版研究覆盖四种组件错误：遗漏、多检、边界错误、类型错误。拆分/合并作为有定义的扩展实验，不必为了显得完整而同时纳入首轮主结果。

## 四、固定候选空间：允许改组件，但不允许改评分的尺子

### 4.1 先建立原文跨度候选集合

在进入修正前，一次性建立 \(U(x)=\{u_1,\ldots,u_m\}\)，其中 \(u=(s,e)\) 是原文中的跨度，来源为：

1. 原有 K 个完整候选图中的有效跨度；所有将参加比较的初始合法图，其跨度和边必须可表示。
2. 单独的组件候选器对全文给出的备选跨度，包括原图未覆盖区域。建议训练一个共享文本编码器上的边界/跨度候选头，不只对已有节点附近做搜索。
3. 对候选跨度进行有限边界扰动，例如左右端点分别在 ±1、±2 个评价 token 内变化，去重并重新评分。
4. 拆分/合并扩展：在进入本轮搜索之前产生候选切分点和合并跨度。不能在搜索中临时增加变量而仍称分数完全不变。

建议先以“保留所有初始候选跨度＋最多 64 个补充跨度”作为工程起点，而非论文确认的最优超参数。补充跨度按候选器得分排序，并对不同句段设置确定性的配额以防全部集中于已有节点。上限和配额只在开发集选择，报告裁剪前后的召回。初始池本身超过资源上限时记录资源失败或使用预先定义的大文档配置，不能偷偷删除某个基线的初始节点。

这是有限支持集。若正确跨度不在 \(U\)，后续搜索不可能恢复它。高覆盖率是可行性前提，不能用更复杂的修正绕开。

### 4.2 状态变量和候选边

对每个跨度设组件状态：

\[
z_u\in\{\varnothing\}\cup\mathcal T,
\]

其中 \(\varnothing\) 表示“不选为组件”。相同跨度的所有合法组件类型是备选状态；两个有重叠且协议禁止共存的跨度不能同时激活。**不要把所有相互重叠跨度的传递连通分量简单设置成只选一个**：长跨度可能与两个互不重叠的短跨度分别相交，这样会错误禁止拆分。

对预先定义的有向跨度对集合 \(P\subseteq U\times U\) 设：

\[
y_{uv}\in\{\mathrm{NONE}\}\cup\mathcal R.
\]

非 NONE 关系要求两个端点激活；自环禁止。首轮小规模验证优先采用全部不相交的有向跨度对，避免把邻域裁剪与方法本身混为一谈。扩展至长文时，可使用“局部窗口＋全文检索 Top-k”的固定稀疏 \(P\)，但要保留初始边，并单报 pair recall。搜索过程中 \(U,P\) 不变。

节点导出 ID 只是序列化编号。内部语义身份使用 `(doc_hash, tokenizer_version, start, end, type)`。节点改类型或跨度就产生新身份，不能沿用旧 ID 的验证通过状态。

### 4.3 为什么不继续冻结最初的 Claim 清单

若允许真实的 Claim→Premise/MajorClaim 改正，还强迫它按最初 Claim 身份满足覆盖目标，就会惩罚正确修改。相反，若随意重算清单，又允许通过退出清单增分。

因此，新主方法**去掉基于当前/初始结论平均入度的奖励**，改成固定候选上的文本证据得分。覆盖异常最多用来安排尝试顺序，不能证明节点错误，也不构成接受条件。无关系的合法组件允许保留。

## 五、证据模型：给组件与关系可复用的判断依据

### 5.1 推荐主实现：训练的、与生成轨迹分离的评分器

采用可训练的文本编码器，对整篇文档或确定性分块编码；由 span 表示、边界表示、长度和文档上下文组成组件特征。长文采用固定分块及跨块表示汇合，记录截断/分块规则，禁止默默截掉远距离关系。

组件头给出：

\[
p_C(t\mid x,u),\quad t\in\{\varnothing\}\cup\mathcal T.
\]

关系头输入原文表示、有序跨度对及端点类型嵌入，给出：

\[
p_R(r\mid x,u,t,v,t'),\quad r\in\{\mathrm{NONE}\}\cup\mathcal R.
\]

关系头可以是 span-pair MLP 或 biaffine 头；这里不主张网络结构创新。span 候选联合关系建模已有基础，可用作实现参照。[Eberts & Ulges, 2020](https://journals.sagepub.com/doi/10.3233/FAIA200321) <!--ref:eberts2020--><!--anchor:section:abstract-->

**评分输入不包括当前预测图、已接受次数和生成器自述理由。**同一 `(x,u,t,v,t')` 使用同一分数表。文本可包含完整篇章上下文，并不是只看孤立句子；限制的是变化中的预测图上下文。高阶图依赖由硬约束及联合搜索承担，这是可比性与表达力之间的明确取舍。

概率表可以按需惰性计算，但键、模型、输入窗口、精度、温度和校准参数必须固定。分数缺失或计算失败时拒绝该候选事务，不能将“未验证”当作 NONE 或概率 0。初始状态得分也无法完整计算时，应返回明确失败/降级身份。

此评分器与生成器是职责和训练过程的分离，不意味着二者统计误差独立。若最终共享编码器或检查点，应如实说明，不用“独立验证”措辞。

### 5.2 训练样本必须覆盖真实预测错误

只用金标准组件训练关系头，会在错误跨度上产生分布错配。建议：

1. 在正式训练集内部按文档做交叉拟合，产生 out-of-fold 初始图和 \(U,P\)。生成某个训练文档候选的模型不得用该文档标签训练；再用这些候选与训练金标构造评分样本。
2. 组件正例：跨度与金标精确一致，类别为金标类型；其他候选按本研究精确抽取协议标为 \(\varnothing\)。另外保留边界近错、类型混淆、多检等困难负例。
3. 关系正例：两个跨度、端点类型、有向连接和关系类型均匹配金标；其余为协议下的 NONE。这里 NONE 表示“金标没有该精确关系”，不是关于真实世界所有潜在关系的断言。
4. 错类型端点和近错跨度也要进入训练；不能仅见过完美端点。训练可补入漏掉的金标跨度以覆盖正例，但校准/评价必须使用真实候选器输出，不能把训练期金标补入规则带到验证或测试。
5. 训练中保留零修改/正确初始图，避免模型学成“只要看到候选就应该改”。预测轨迹负例与人工扰动混合；只用人工噪声容易低估真实错误。

起步损失为：

\[
\mathcal L=\mathcal L_{\mathrm{span}}+\alpha\mathcal L_C+\beta\mathcal L_R.
\]

三项分别为候选头、组件状态和关系状态监督。首版不再堆叠强化学习、专门图神经网络和轨迹偏好损失；若简单实现不能区分好坏修改，先查标签、候选和校准。NONE 数量较大时可分层采样，但必须保存采样率，并在自然候选分布上重新校准/验证，不能把平衡采样后的概率直接当真实先验概率。

交叉拟合训练额外消耗必须计入。资源不足时可改用训练集内部独立划分，但将数据利用率和评分器质量下降作为明确代价，而不是把训练内预测当成 OOF。

### 5.3 校准与可解释性

组件头和关系头分别做温度缩放作为起点，在未用于其参数训练的开发样本上拟合；其适用性需验证。[Guo et al., 2017](https://proceedings.mlr.press/v70/guo17a.html) <!--ref:guo2017--><!--anchor:section:abstract-->

报告 NLL、Brier、可靠性图和分类别误差；关系头同时报告全体候选和实际尝试事务中的分布，防止 NONE 占多数掩盖新加边风险。不能从“校准后的 0.9”推出每个被选事务都有 90% 正确率：搜索选择会改变分布，域外迁移也会破坏校准。

日志中保存对应原文跨度、状态概率、分数差和被修改端点。可以额外生成简短证据说明，但不让自由生成的说明成为唯一接受依据；“能引用原文”不等于该引用证明了类型或关系。

## 六、统一目标：使用固定因素的能量，不使用动态均值

令概率进行固定 \(\epsilon\) 平滑并归一化，定义组件相对空状态的分数：

\[
a_u(t)=\log\frac{p_C(t\mid x,u)}{p_C(\varnothing\mid x,u)},\qquad a_u(\varnothing)=0.
\]

关系分数采用相对 NONE 的条件对数比：

\[
b_{uv}(t,t',r)=\log\frac{p_R(r\mid x,u,t,v,t')}{p_R(\mathrm{NONE}\mid x,u,t,v,t')},
\quad b_{uv}(t,t',\mathrm{NONE})=0.
\]

端点未激活时只允许 NONE，贡献为 0。所有允许的类型组合是同一张冻结因素表的不同条目；不能在改类型后更换验证提示、掩去不利类别再重新归一化。

图证据能量为：

\[
V(G)=\sum_{u\in U}a_u(z_u)
 +\lambda\sum_{(u,v)\in P}b_{uv}(z_u,z_v,y_{uv}).
\]

修正接受目标为：

\[
J(G;G_0)=V(G)-\eta_C\,|C(G)\triangle C(G_0)|
                 -\eta_R\,|R(G)\triangle R(G_0)|.
\]

其中组件和关系都按语义身份组成集合，\(\triangle\) 为对称差；同跨度改类型计一删一增，边端点改动也改变关系身份。\(G_0\) 在一条轨迹开始后不变。这个代价是**锚定初始图的偏离惩罚**，不是声称找到了最短编辑路径。它也不是按“本次编辑数”惩罚后每轮重置，因此不能通过多轮小步逃避总偏离代价。

### 6.1 目标的性质和边界

- \(U,P\) 和因素表固定，所以不同节点数的图在同一能量定义下比较。没有通过删去一个节点缩小均值分母的奖励。
- 不选组件/不连边是明确的零基准，不累计海量 NONE 的负对数项；但这不意味着类不平衡已经解决，仍需校准、阈值和预测数量诊断。
- 这是有条件对数比组成的**判别能量**，不是严格归一化的图联合概率，更不是 F1 的无偏估计。因为关系的 NONE 基准依赖端点类型，不能把整个式子简单解释为一套完整概率模型的最大似然。
- 类型仍可改变关系因素值；这是必要的联合建模能力，也仍可能被错误评分器利用。固定因素表只解决“比较规则漂移”的一个问题，不解决所有代理优化失真。
- 正分因素相加仍可能偏好过度分割或过多连接；固定候选并不能消除数量偏置。组件/关系头也可能重复使用同一文本线索，它们不是两份独立证据。通过精确负例、偏离代价与开发集权重控制，并报告预测组件数、跨度长度、边密度及按初始节点度数分组的误改；若仍有系统性偏差，应修目标而不是隐藏这些统计。
- 错误节点若被组件头高置信支持，仍可能保留；真实孤立节点若组件头误判，也可能被删除。不能写成不会漏检/误删。
- 主方案不额外加覆盖奖励、自然语言解释质量奖励或基于预测图规模的归一化。需要时作为单独消融，而不隐式混回目标。

### 6.2 候选选择与修正的接口

机制实验先锁定同一个 \(G_0\)，比较 BR-O、BR-C 与新方案，避免把更好的初始化算作修正收益。系统实验可用 \(V\) 对同池完整合法图重排序，再固定所选 \(G_0\)；此时设置“新评分器仅重排序”对照。

不能比较来自不同 \(G_0\) 的 \(J\) 大小来断言哪条轨迹更优；不同轨迹的偏离参照不同。跨方法最终比较使用同一金标准评价和成本指标。

## 七、组件动作与依赖闭合事务

### 7.1 允许的动作

|动作|组件状态变化|能力与限制|
|---|---|---|
|Retype|同一跨度 \(t\to t'\)|覆盖整个语料类型表，而非只 Claim/MajorClaim|
|Respans|旧跨度关闭、新跨度激活，可同时改变类型|新跨度必须在 \(U\)，不是任意生成新文本|
|Insert|\(\varnothing\to t\)|能补回原图缺失组件，前提是原文候选器提供了跨度|
|Delete|\(t\to\varnothing\)|删除误检；不是为提高平均分自动删除孤立节点|
|RelationOnly|组件不变，关系增删、改标签或反向|保留必要的纯关系修复能力|
|Split/Merge（扩展）|一个跨度换成两个，或反向|以成组动作执行；两个短跨度需独立合法，不能把长跨度的边一律复制过去|

首版主结果为前五种。Split/Merge 有独立候选、成本与失败类型，只有通过单独检查才加入扩展版，不能把未实现能力写进摘要。

### 7.2 什么叫“所有受影响关系”

设组件修改涉及旧、新跨度集合 \(A\)。受影响因素为：

\[
P_A=\{(u,v)\in P:u\in A\ \lor\ v\in A\}.
\]

这里包括入边、出边、当前无边的潜在连接，以及与原图中未相邻组件的连接。只更新原图一跳已有边不够：补回一个孤立漏检组件时，它在原图根本没有邻居。

事务分四步：

1. 在副本中应用组件动作，关闭旧组件状态。
2. 使受影响关系的旧判断失效。旧边可作为候选意图，但其原“通过”标志不得继承。
3. 在修改后的端点状态下对 \(P_A\) 重建关系；\(P\setminus P_A\) 保持不变。
4. 对完整候选图检查合法性、逐项证据和 \(\Delta J\)，一次提交或全部回退。

若启用全图无环约束，局部边选择也必须相对固定外部边检查是否形成跨区域环。若最佳修改还需改变外部边，首版选择拒绝/等待另一次明确事务；不得以“局部”名义悄悄扩大边界。可扩展依赖闭包，但必须重新记录范围和成本。

### 7.3 为什么中间分数可以下降

组件改正后，原关系可能暂时消失；如果要求每个内部步骤增分，就会阻断“先换端点、再重建正确关系”的路径。

因此，不评价或提交残缺中间图。只要求事务完成后的 \(J(G')>J(G)\)。内部暂时少边或指针尚未重建是实现暂存状态，不能输出给评价器，也不能作为下一次事务的起点。

此外，最终某项关系得分也可以小幅下降，只要组件证据增加足以补偿且所有新增/语义改变的保留边通过门槛。**不能要求组件 F1 或关系 F1 在测试时单调**，因为算法看不到测试金标。

## 八、局部关系重建与接受规则

### 8.1 固定组件后的局部求解

组件动作确定后，受影响跨度对的系数 \(b_{uv}\) 已固定。将每对的 NONE 和合法关系标签设为 one-hot 变量，最大化与整个 \(J\) 完全相同的局部项；不受影响项是常数。约束包括有效端点、同对标签互斥、协议关系限制，以及启用时的全局无环约束。

推荐首版用局部 ILP 或有明确上限的枚举/束搜索。小图尽量精确求解，长图允许时间上限及 best feasible solution，日志记录 `optimal/feasible/timeout/no_solution`。结果不最优时，只能称“找到一个可接受事务”，不能称最优重建。

RelationOnly 的作用域也需固定：以待核查的有向跨度对为种子，令 A 为其两个端点，对 P_A 重建，组件完全不变；这允许相关的反向、替代边一起竞争，而不是默认每次重跑全图。选择预算匹配的单对作用域作为消融。

**不直接把旧 BR-C 的密度/连贯性目标用作内层接受目标。**否则内层偏好与外层 \(J\) 不一致，可能提前丢掉外层更优结果。BR-C 可作为额外候选生成器，但所有最终候选仍需统一评估；若这么做，应注明不保证找到局部 \(J\) 的最佳响应。

### 8.2 组件证据门槛

对修改的每个新激活/重分类组件，要求对应 \(p_C(t\mid x,u)\ge\tau_C\)；独立 Delete 要求 \(p_C(\varnothing\mid x,u)\ge\tau_D\)。阈值由开发集确定，不固定把某个自述概率当真。

Respans/Split/Merge 中被关闭的旧跨度不要求另过 Delete 门槛，因为这是替代假设；但新跨度逐个过 \(\tau_C\)，且每个组件动作需满足：

\[
\Delta A_C=\sum_{u\in A}\big[a_u(z'_u)-a_u(z_u)\big]\ge-\varepsilon_C.
\]

首版取 \(\varepsilon_C=0\)，不允许关系得分大涨掩盖组件证据明确变差。它仍允许多个近似组件假设由关系重建后的得分决定。放宽 \(\varepsilon_C>0\) 作为消融，检验更多联合恢复能否补偿误改；不要把严格与放宽版本的结果混合。

这个限制会错过一部分“组件头判断错、关系证据其实能纠正”的真实修改，属于有意的风险—召回取舍，并不声称是所有联合修复的最优策略。

### 8.3 关系证据门槛与整体接受

对事务中所有新增或语义端点变化后仍保留的非 NONE 边，要求：

\[
p_R(r\mid x,u,z'_u,v,z'_v)\ge\tau_R,
\qquad b_{uv}(z'_u,z'_v,r)>0.
\]

可以直接在局部求解时禁用未过门槛的标签，不必求解后反复丢弃。纯关系事务中的新增、改标签和反向也遵守同一规则。未改变的外部边不会因此自动成为“已验证正确”，只是不在当前事务范围。

最终接受条件：

\[
\mathrm{Accept}(G\to G')=
\mathrm{Legal}(G')\land \mathrm{ComponentGate}(G,G')
\land\mathrm{EdgeGate}(G,G')
\land[J(G';G_0)-J(G;G_0)>\delta]
\land\mathrm{BudgetOK}\land\mathrm{Unvisited}.
\]

\(\delta>0\) 是数值/接受间隔，另设明确的浮点容差。是否将其扩大到具有实际风险作用的阈值需要开发集支持；默认最小严格间隔并不保证低误改率。

拒绝原因细分为候选缺失、跨度冲突、类型/端点非法、组件证据不足、新边证据不足、全图约束失败、净分不足、重复状态和预算耗尽。全部记账，不只保存成功案例。

## 九、完整算法与停止条件

```text
输入：原文 x、固定初始候选池 H、生成器/评分器身份、语料协议、预算 B

U, P ← BuildFrozenUniverse(x, H)          # 不读取测试金标
F ← 冻结评分函数及其惰性缓存；锁定哈希
G0 ← 选定的合法初始图；机制对照中各方法共享 G0
若不存在合法可评分 G0：返回显式失败，不丢掉该文档
G ← G0；visited ← {Canonical(G)}

while 预算允许：
    Q ← 有限组件动作 + 有限纯关系动作
    按不确定性/备选差距排列 Q；稳定规则处理同分
    本轮候选集合 S ← 空
    for action in 前 L 个未尝试动作：
        在副本中 Stage(action)
        检查组件证据门槛
        标记并废弃受影响旧边判断
        G' ← 用同一个 J 对依赖闭包内关系重建
        全图检查并计算 ΔJ
        记录动作、得分、证据、求解状态和消耗
        若完整接受条件成立：加入 S
    若 S 为空：停止并记录未找到可接受事务
    G ← S 中 J 最大的图；同分按更小偏离、再按规范键确定
    提交整个事务；visited 加入 Canonical(G)

返回：最后一次完整提交的 G、全轨迹、成本和停止原因
```

候选排序是预算分配，不是正确性判定。初始可按节点非当前状态概率、边竞争标签差距排序；不要同时学习一个复杂路由器再把其收益归给事务机制。所有候选来自固定 \(U,P\)，每个状态的动作列表有限，尝试过的 `(before_hash, action_hash)` 不重复。

建议新配置起点：每轮最多 8 个组件动作＋8 个关系动作，最多 3 轮、每轮提交 1 个事务；这些是可调整的新建议值，不是历史实验设置。硬限制还需覆盖模型输入/输出 token、编码器/关系头评估数、求解器时间、总墙钟时间和接受次数。只限制 LLM 输出 token 不足以控制本方案计算量。

便于落地的起步参数：损失权重 α=β=1，能量权重 λ=1，η_C=η_R=0.05，ε_C=0，τ_C=τ_D=τ_R=0.5，δ=10⁻⁶、浮点容差 10⁻¹²。这些仅用于首轮工程和开发诊断；多类别情况下 0.5 可能过严，不能直接当最终实验配置。先分别检查概率和数量偏置，再按开发集选择阈值及 λ/η，记录全部尝试及选参准则，不在测试集搜最优组合。冻结后的阈值表和校准身份是发布方法的必要组成部分。

事务执行中预算耗尽，丢弃未提交副本，返回最后一个完整合法状态。若评分器初始化就失败，应返回基线或失败状态并标明降级原因，不能以“新方案成功”掩盖。

## 十、能证明什么，不能证明什么

### 10.1 固定条件下的三个有限性质

1. **状态合法性。** 若初始提交图合法，每次仅提交经过完整约束检查的图，则所有提交图合法。这里合法仅指协议，不指语义和金标正确。
2. **单轨迹代理分数严格增加。** 固定 \(U,P,F,G_0\) 且评分可重复时，接受条件直接保证 \(J\) 严格增大。预算与有限状态空间保证停止；不保证全局最优。
3. **端点证据不复用。** 缓存键包含原文、跨度、类型、方向、模型和协议身份时，改变任一语义端点不会沿用旧键。该性质是数据依赖正确性，不是模型推理正确性。

### 10.2 不能承诺的性质

不保证 F1 单调、不会误删、所有漏检都能补回、搜索得到全局最优、修改数最少、跨域仍校准，或新方法必然优于 BR-C。BR-C 的组件不变性质在本方案中明确不再成立。

禁用组件动作后得到的是“新评分目标下的关系修正”，**不是与原 BR-C 完全相同的算法**。二者应以不同配置名保存。

### 10.3 必须保留的失败反例

- 错误高置信组件：若评分器错误地偏好一个非组件，Insert 仍可能增分并过门槛。
- 有价值跨度被候选裁掉：任何后续修正都无法补回；必须改候选器而不是增加搜索轮次。
- 两个组件必须同时变化才能改善：单组件事务可能陷入局部最优；有限双组件交换/束搜索是扩展，不能以单点局部最优冒充联合全局最优。
- 过度分割的错误候选分别取得较高分：两个错误短组件的分数之和可能超过一个正确长组件；非重叠约束和固定因素表都不会自动阻止这种误改。
- 固定文本条件忽略某些图级依赖：分数可比较，但可能缺乏足够判别力；同评分器全局解码同样受限。
- 类型改变移除旧关系：即便类型更正确，因旧关系因素很高且偏离代价较大仍可能被拒绝；通过误拒统计检查此取舍。

这些反例应进入讨论或测试，而不是等评审发现后补充。

## 十一、一个读者能看懂的示例

原文示意：“学校应该延长图书馆开放时间，因为许多学生晚上才有空学习。”

假设初始图把前半句错分为 Premise，后半句正确分为 Premise，并缺失后半句到前半句的 Support 边。

1. 组件候选给前半句提供 Claim 备选，且其组件证据优于 Premise。
2. Stage Retype 后，所有涉及该跨度的关系判断失效，后半句→前半句这一此前不存在的边也在重建范围内。
3. 在新端点类型下计算 Support/NONE 等概率，构建候选关系。
4. 同时评价“改类型＋补边”与保持原图，而不是只看改类型后覆盖率是否提高。
5. 证据不足就不改；通过则提交整个包。

若前半句在初始图完全缺失，但在全文候选器的 \(U\) 中，则用 Insert 完成类似过程。若 \(U\) 也没有该跨度，本方案无能为力。这个例子仅解释流程，不是实验样本或成功率证据。

## 十二、验证计划：必须分清评分器、动作和事务的贡献

### 12.1 四个预先写清楚的假设

|假设|主要比较|否定/收窄条件|
|---|---|---|
|H1 新目标减少动态覆盖引起的表面增分|同动作池，旧目标 vs 新目标；真实轨迹增分/金标变化配对|只通过构造例，而真实净修复无改善：仅支持漏洞修补，不支持一般性能贡献|
|H2 组件修改与关系闭合重建比顺序独立修改更有效|同评分器、同候选、同预算，串行基线 vs 完整事务|与串行方法接近且成本更高：事务价值不成立或仅为实现保证|
|H3 组件证据门槛降低误删/误改|完整方法 vs 无组件门槛；报告恢复—破坏曲线|降低修改率但净收益更差：门槛不应包装为必然可靠性提升|
|H4 受控局部搜索有质量—成本优势|同因素表和约束，局部事务 vs 全局/受限 ILP|全局方案同样便宜且更好：转向联合解码，或缩小局部方案主张|

### 12.2 核心对照矩阵

所有机制对照使用同生成器检查点、同初始池、同 \(G_0\)、同评价；有监督评分器的额外数据和训练资源必须向对应强基线开放。

|编号|方法|目的|
|---|---|---|
|B0|固定初始图，不修正|零修改参照|
|B1|原 BR-O|旧动作与旧目标历史路线；重新运行才可用于新比较|
|B2|原 BR-C|固定组件的保守参照|
|B3|同池 Self-Refine 风格整图反馈修改，预算匹配|通用自修正是否已足够；称“适配基线”，不冒称官方 AM 实现|
|B4|新评分器，仅做 RelationOnly|区分换评分器与开放组件动作|
|B5|组件头独立选组件 → 全部关系重新预测/解码|排除更强验证器与重预测本身的解释|
|B6|新动作/评分器，组件步单独接受，再进行关系步|检验允许中间下降和整体接受是否必要|
|B7|同 \(U,P,F\) 的全局结构化解码/ILP|检验局部事务相对普通联合求解的增量|
|M|本方案完整事务，四种组件动作＋RelationOnly|被检验的方法|

B7 小图可精确求解；长图使用相同墙钟上限并报告最优间隙/是否只有可行解。存在额外组件门槛时，需给出“同静态可接受状态限制”及“无门槛联合解码”两种明示口径；不能让 B7 被更严约束，而本方法不受约束。路径相关门槛不能悄悄当作静态可行域完全等价，必要时分别报告。

必要消融优先级：

1. 新目标 vs 旧目标，动作候选相同；避免只比较两个完整大系统。
2. 同新目标，无组件门槛/完整门槛；编辑惩罚为 0/非 0。
3. 串行接受 vs 事务接受；关系闭包 vs 仅保留原 ID 关联边（后者是诊断性错误基线，不部署）。
4. 仅使用初始候选池跨度 vs 加全文候选器；冻结组件时只改关系。
5. 组件评分器/关系评分器更换或弱化；同模型提示验证作为成本对照，不称独立裁判。

不把所有消融机械做完整笛卡尔积。先完成能够推翻中心假设的对照，再按结果定位失败机制。

其中 H1 的评分消融应单独构造“评分形式 × 组件门槛”的 2×2 检查：在共享组件/关系证据表和提议池上，用同一关系阈值产生旧式覆盖/连贯性统计，再与新能量比较，两边分别开启/关闭组件门槛。这样避免将更强评分模型或门槛阻断归因于消除动态分母。这个共享证据的旧式评分对照不是原 BR-O 的逐字复现，应与 B1 分开命名。

### 12.3 指标必须与端点变化对齐

主指标：组件 exact-span+type micro-P/R/F1，端到端有向关系 exact-endpoints+endpoint-types+relation-type micro-P/R/F1。沿用当前评价定义并记录版本。另报去除端点类型条件的关系指标，但作为次级指标，不能择优替换主指标。

机制指标：

- 初始正确组件保留率、错误组件移除量、遗漏恢复量、边界/类型分别修复量；分母为 0 时 NA，并给分子分母。
- 初始正确关系破坏率、遗漏边恢复量、错误新增量、TP/FP/FN 前后变化。
- 关系误差按端点错误/端点正确但连接或标签错误拆开；不同端点可匹配时需预先固定匹配顺序，避免重复归因。
- 成功和失败事务的接受比例、代理增分与真实质量变化的对应关系。把“J 增加但组件或关系 F1 降低”的比例明确列为诊断指标。
- \(U\) 的精确组件召回、\(P\) 的可达关系召回，以及受约束可达空间的离线诊断。不能把逐文档最佳 F1 的平均称为语料 micro-F1 的严格上界。
- 所有文档的实际成本、失败/降级率、额外训练成本；缓存逻辑成本与本次执行成本分开。

关系提升未必来自边推理更好：只改正一个端点类型就可能让多条旧连接变成 exact-match TP。必须同时报告“端点固定下的关系判断”和“端到端整体恢复”，二者都是有价值的结果，但解释不同。

### 12.4 统计和数据使用

建议固定 5 个训练/推理种子（可与既有 17/29/43/71/101 计划衔接），这是新实验建议，不是已运行事实。记录各种子，不把多次生成当作独立训练重复。

主比较预先指定 M vs B5、M vs B6、M vs B7；辅助比较控制多重检验。以文档为配对单位重采样并在每次重采样中重算语料微平均 F1，而不是对边做独立 t 检验。报告差值、区间及种子敏感性；小数据/少数类样本不足时明确不确定性。

评分器训练仅用训练标注；开发集分为校准、超参选择和尽量独立的选择后审计用途。数据小可在开发集内部交叉拟合，但必须说明折法；不能在同一小集合上反复调几十个参数后宣称风险保证。测试集只作冻结后的最终评估。已经反复看过的测试结果要标明探索性，不追认“预注册”。

跨域评价使用 AAEC 学得的候选器、评分器、校准和阈值，不能用 CDCP 金标重新调参后仍叫零样本。原有粗标签映射必须保留；在目标域诊断校准失效，不把迁移改善写成由设计自动保证。跨集泛化问题有现有研究警示，但其句子级结果不是本方法的直接证据。[Feger et al., 2025](https://aclanthology.org/2025.acl-long.1164/) <!--ref:feger2025--><!--anchor:section:abstract-->

## 十三、可行性闸门：先验证最可能失败的地方

以下是建议的开发验收规则，应在开展相应新实验前确认并冻结；不是已达标结果，也不是武汉大学官方要求。

|阶段|先做什么|继续条件|若失败|
|---|---|---|---|
|G0 协议|检查真实语料转换、标签、坐标、初始图和评价脚本|同图在所有对照中得到相同指标；gold 不进入推理|先修协议，不能靠调方法掩盖|
|G1 候选|在开发集测 \(U,P\) 的召回与规模|覆盖率相对初始图有可利用空间；可先以组件精确召回 ≥95% 为目标，同时报告成本|扩展候选器；若空间无提升，不能主打漏检恢复|
|G2 接受判别|收集真实候选事务，按金标评价其好坏|J/门槛能在 held-out 开发轨迹上取得有用净收益；风险曲线优于全接收|先改评分器；不进入复杂搜索堆叠|
|G3 强简单对照|M vs B5/B6/B7，至少两个域内语料|不是只赢旧 BR-O；有稳定质量或相同质量下的成本/误改优势|收窄创新，必要时选择简单基线做主方法|
|G4 稳健性|多种子、预算曲线、弱验证器、域迁移|结论在声明范围内成立，并诚实呈现失败条件|把作用域限制写进摘要和结论|

G2 的好坏标签建议分别保留 ΔComp-F1、ΔRel-F1、正确对象破坏数，不先合成一个掩盖冲突的“好编辑”标签。若必须设门控目标，可将“关系提升且组件不退化”作为一条预设审计口径，并另报存在权衡的事务。总体判定仍以 corpus 级结果为准。

为避免“显著但几乎无价值”，正式实验前可与导师约定最小实际效应，例如主关系 F1 改善至少 1 个点，或在质量接近时显著降低成本/误改；阈值是研究决策，不是领域公认标准，不能看到结果后再改。

## 十四、实现接口、复杂度与算力代价

### 14.1 建议新增接口

```text
FrozenUniverse: doc/tokenizer/schema hash, spans, directed_pairs, conflicts, provenance
EvidenceTable: scorer/calibration hash, component probabilities, typed-pair probabilities
GraphState: span states, pair states, canonical semantic hash
EditTransaction: action, changed spans, affected pairs, staged graph, rejection reason
RepairTrace: initial/final graph, factor deltas, gates, solver status, budgets
```

建议模块为 `universe.py`、`evidence.py`、`transactions.py`、`joint_repair.py`、`joint_audit.py`，保持旧 `repair.py` 可独立运行。每个 run 保存旧/新方法全名与配置哈希，不只写 Full。

至少测试：ID 重排不改变能量；改类型不能复用旧边缓存；Insert/Delete 后无悬空边；替换事务完整回退；边界越界和重叠；零边/零组件；同分不接受；候选缺失；预算在不同阶段中断；非法循环；词元坐标不一致；不同语料 MajorClaim 处理；固定外部边时跨闭包成环；评分提高却 F1 降低的反例。

### 14.2 复杂度与资源

设候选跨度数 m，类型数 T，关系标签数 R。组件表 O(mT)，完整类型条件的关系表上限 O(m²T²R)；使用一次文本编码＋轻量头和惰性缓存降低实际代价。若每个 pair 都调用一次大模型，成本可能非常高，不建议作为主实现。

每个涉及 a 个跨度的事务触及 O(am) 对；但编码器、类型组合和求解器开销都必须计入。ILP 的最坏复杂度不能因局部变量较少就宣称多项式；报告实际变量数、超时和最优间隙。

主要额外成本来自评分器训练与训练候选的 OOF 生成。先用真实训练/开发小批量测显存和吞吐，不在没有 GPU 型号、样本长度和模型实测时承诺训练小时数。本轮不下载数据、权重或启动付费计算。

## 十五、创新表述、论文结构与最终选择条件

### 15.1 可以使用的贡献草稿

> 针对预测后图修正中组件变化导致关系证据失效、以及动态图统计可能产生表面增分的问题，本文研究文本证据约束的组件—关系事务式修正方法。方法在固定候选与因素空间中，将组件替代及其受影响关系的重建组成整体事务，并结合组件证据门槛、语义端点核验和统一能量决定接受或回退。通过同候选、同评分器及预算控制的对照，分析其净修复收益、正确结构破坏及适用条件。

目前只能作为设计稿。真正写成学位论文贡献时，最后一句须对应已经完成的新实验，并替换为证据允许的具体发现。

不建议使用：“提出首个组件关系联合修复框架”“保证修复不降低性能”“实现最小修改最优论辩图”“解决 LLM 幻觉”“无需监督的可靠验证”。本方案推荐的评分器需要监督，不能回避。

### 15.2 与第一项创新形成闭环，但不制造虚假依赖

第三章结构保持增强面向训练期输入变化与监督保持；第四章事务修正面向推理期输出变化与关系依赖。二者可以用“组件变化时如何维护关系信息”形成共同问题线索，但研究对象不同：前者改训练文本，后者不改输入文本。

建议先固定第三章检查点研究修正，再做“无结构增强/有结构增强 × 无修正/有修正”的 2×2 组合实验。只有交互证据支持时才写协同增益；不能因两个模块放在同一系统中就宣称相互促进。

### 15.3 第四章拟定结构

4.1 问题与失败机制 → 4.2 固定候选及语义身份 → 4.3 文本证据模型与训练 → 4.4 依赖闭合事务 → 4.5 统一目标及接受算法 → 4.6 性质、复杂度和边界 → 4.7 主对照与机制实验 → 4.8 失败分析。

Related Work 使用配套文献文件中的主题组织。BR-C 放在算法演进与对照中，而不是写成已被新方案全面推翻。旧实验表按实际算法身份保留/迁移，不能直接改名。

### 15.4 最终评审式判断

技术上：组件候选、分类证据、约束求解和原子提交都有可实现路径，可行性较高；它不是直接打开已有开关即可完成。

创新上：比“保守固定组件”有更完整的研究问题，但各零件大多已有先例。真正能否成为有分量的方法贡献，取决于**同评分器的强简单/联合解码对照**是否仍显示事务设计的必要性，以及失败机制在真实数据中是否具有足够影响。

实证上：新设计当前没有可宣称的正式收益。若只证明某构造漏洞被阻断，而真实提升来自新评分器，应将评分器或误差分析作为主要贡献；若全局联合解码更好，就改选更好的主路线，而非为了维持命名继续堆模块。

最值得立即开展的下一步是 **G1 候选可达性审计＋G2 修改接受判别实验**。这两步比先把全部操作接进正文更能判断路线值不值得继续。
