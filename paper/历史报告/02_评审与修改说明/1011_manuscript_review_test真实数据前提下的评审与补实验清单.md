## 二、先处理的稿内核对：不等于要求新增大实验

### R1：解释 I0 关系数量的规律，确认端到端输入边界

**性质：待澄清的协议问题；目前不据此判定泄漏或结果不真实。**

**证据锚点：table: 表H-5，T0/I0与T1/I0的12行计数；表5-6各源数组的I0计数。**

表H-5中，两种语料、两个 I0 配置、三个种子均有 `FP = FN`。按严格集合计数，这意味着各行 `TP + FP = TP + FN`，即预测关系数恰好等于金标关系数：AAEC 每次为809，CDCP 每次为252。CDCP 表5-6还呈现按源数分组的对应现象。

这不是造假证据，也不能仅凭它推断用了金标，但它值得优先解释，因为论文将任务定义为从原始文本出发的端到端抽取。

建议作者先核对并在文中简短说明：

1. 关系条数由模型自由生成，还是受到固定槽位、候选协议或后处理的数量约束？该约束如何获得？
2. 测试时是否完全不提供金标组件、金标关系数或按源数的金标数量？
3. 若属于自然产生的汇总巧合，补一张逐文档预测数量与金标数量的分布/差值摘要即可，无需因该规律本身重跑。
4. 若属于表格导出或统计口径问题，修正表格并重新计算受影响指标；若实际使用了测试金标数量，则需移除该信息、重新评价受影响配置，并与原条件分开报告。

**完成条件：读者可以从稿件理解输出数量的来源，且该来源符合声明的测试输入边界。**

## 三、最有价值的补实验

下面按信息价值与成本给出建议顺序。E1、E2直接对应两个核心研究内容；E3、E4取决于希望保留多强的外部比较和效率主张。没有要求所有项目都做。

### E1：成对学习的留出改写稳健性检验

**优先建议；用于补强贡献一。**

**证据锚点：table: 表3-4；absence: §3.6、图3-3与附录H — expected 留出文本上同时报告预测一致性与正确性的成对机制检验; checked 训练消融、训练曲线、增强审核及附录诊断。**

现有同视图、同掩码的 NoPair / CompPair / T1 对照已经正确，不需要重新设计一套同名消融。缺少的是：成对约束是否在未参与训练的表达变化上，减少错误波动，而不只是降低训练集上的 JS。

**建议方案：**

1. 使用未参与训练、增强、校准和策略选择的源文档，按预先固定规则构造留出改写评测。可以从现有正式测试文档构造每篇一次改写的诊断集；它是新增的留出改写条件，不是新增独立语料，也不能再宣称从未看过其源测试结果。
2. 生成、验收和坐标输运规则在观察本轮模型结果前冻结。人工判定者不看待比较模型的输出；保留所有尝试、接受、拒绝及原因，不能只留下模型表现好的改写。
3. 用已有 NoPair、CompPair、T1 检查点评价相同原文与相同改写。优先复用检查点，因此这一部分主要增加评测与人工验收，而非训练。
4. 如果先做较小诊断集，应事先固定抽样规则和规模、报告每层源文档数，并将结果定位为有限精度诊断；不以任意几十个样本承诺检验功效。

**必须一起报告的指标：**

| 层次 | 指标 | 避免的误解 |
|---|---|---|
| 正式端到端输出 | 原文与改写文的严格组件/关系 F1、两者差值 | 不能用金标跨度上的头部表现替代端到端效果 |
| 对应因素诊断 | 组件/关系分布差异、标签翻转率 | 一致性提高不一定代表正确性提高 |
| 一致且正确 | 两视图均正确的因素比例，以及两视图一致但均错误的比例 | 防止模型稳定地犯同一个错误却被认作改进 |
| 错误类型 | 内部/跨边界、正关系/NONE、CDCP完整多源对象 | 检查关系感知目标是否作用于预期依赖 |

因素诊断可用经过核验的对应和跨度定位，但必须标明其为受控诊断；端到端预测输入仍仅含文本。重采样以源文档为聚类单位，不能把同一原文的多个因素或变体视作独立样本。

**若还愿意增加训练：**建议预先锁定一个新增种子预算，例如在现有3个种子基础上固定再加2个，对 NoPair、CompPair、T1 使用相同视图、掩码和预算。这里的5个种子只是成本折中，不是保证显著或保证充分功效的标准。主要差值看 T1−NoPair；CompPair用于定位组件项与关系项的作用。

**如何解释结果：**

- 如果留出改写的一致且正确比例提高，同时正式抽取不受损，可直接支持对应学习的设计动机。
- 如果只有训练 JS 或测试一致性提高，而正确性不提高，应将成对项定位为稳定性约束，不宣称它已解释全部 F1 增量。
- 如果扩展实验仍不确定，保留效果量与区间即可，不追着 p 值不断加种子，也不需要废弃整套训练方法。

### E2：依赖闭合“何时有用”的分层归因

**优先建议；先做现有预测的再分析，确有需要再增跑。**

**证据锚点：table: 表4-3、4-4、4-6、4-8b、5-5a、5-5b。**

当前比较已经覆盖 RelationOnly、Sequential、Single、SetLocal 和 Global。不要再把“缺少这些基线”当问题。真正值得回答的是：平均优势较小时，是否在需要修改端点、且关系依赖确实受到影响的文档中体现价值？

**第一步：不新训练，复用现有冻结输出与账本。**

- 在查看方法差值前写下分层规则。以共同的 T1/I0 初始图为基准，划分“关系错误但端点已经正确”“存在可从冻结候选池恢复的错误/缺失端点”“正确端点尚未入池”等情况。
- 文档级分层可采用固定优先级形成互斥组；如果组允许重叠，明确报告重叠，不将各组数相加当总量。
- 这些分层可以在离线分析中使用金标，但不能让在线修正器据金标选择动作。不要按“Single比Sequential好”的文档反向定义有利子集。
- 对同一分组的文档，所有方法使用完整预测与完整金标重新计算严格 F1；保留 FP，不只展示被恢复的金标对象。
- 对对象级诊断，另报“具备恢复条件的金标关系数、恢复数、原 TP 损失、错误新增、事务接受/拒绝”。不要把仅有金标分组的恢复率冒充包含 FP 的完整 F1。
- 重点比较 RelationOnly、Sequential、Single、Global；SetLocal与Single完全一致时如实写一致，不必为它另开大规模性能实验。

**第二步：如果需要进一步拆开候选扩充与决策的作用，可选做一个2×2诊断。**

| 候选条件 | 固定组件的 RelationOnly | 组件可变的 Global/正式 I1 决策 |
|---|---|---|
| 仅保留共同初始生成产生的候选对象 | A | B |
| 加上正式跨度/类型/源组提案 | C | D |

共同的初始对象必须在四格中保留。先在候选并集上用同一冻结评分器求分，再通过候选掩码形成两个池；组件/关系标签规则、合法性、预算、校准参数保持一致，不为各格用测试金标重新调阈值。这回答的是给定评分器下的候选与组件可变决策作用，不是全部系统的无条件因果分解。

复用评分用于质量归因时，应注明缓存复用；如果同时比较实际端到端成本，应分别计入各配置真实需要的提案与评分成本，不能把缓存后的近零费用当作部署费用。

**如何解释结果：**

- 如果优势集中在“端点需修复且候选可达”的分组，可把机制作用范围讲清楚，不要求全测试集巨大涨分。
- 如果不同决策几乎始终相同，则保留依赖闭合的正确性、合法性和可审计接口价值，将复杂动作降为可选实现。
- 新增的事后分层先作为探索性解释；若要把某个分组确认为核心规律，需在固定规则后的独立补充条件中检验，不能只报告最有利分组。

### E3：CDCP外部对照的共同表达能力检查

**建议补，通常可先复用已有预测；用于提高外部比较说服力。**

**证据锚点：table: 表G-1至G-3、表5-6；text: 附录G.2“当前外部适配接口最多表达3个源成员”。**

外部基线已经存在，不需要再把“没有具名方法”列为缺项。但 CDCP 测试包含8条四源以上关系，而外部适配接口最多3源；同一评价器不等于相同表示能力。该差异不能解释所有15—17 pp的系统差值，但必须限制其解释。

最小补法：保留全测试结果，再在“文档内全部金标关系均可由双方接口表达”的固定文档子集上，重新评价所有系统。对所选文档仍评价全部预测与全部金标；不要只删除不便匹配的预测 FP。报告子集文档数、组件数、完整关系数与排除条件，并将其标为诊断子集而非新主榜。

更强补法：若外部方法的真实架构允许，修正适配接口使其能够表达所需长源集合，再按统一完整对象协议重评；若需要实质改变模型结构或重训，应明确这是适配版，而不是原方法原封不动的结果。

不必为了论文完整性强行补十余个外部系统。优先把已经比较的两个系统的实现身份、表示能力及成本说明清楚。

### E4：风险—质量—成本曲线

**有条件建议：希望强化效率或安全取舍时做；不属于所有论文必须补的项目。**

**证据锚点：table: 表4-4、4-6、4-9、H-4。**

当前已有成本表、等预算重生成、弱评分回退和求解规模扫描，不能称“没有效率实验”。尚欠的是不同资源档位下的取舍曲线。

建议在现有正式配置附近预先锁定少量追加预算档位，对修复和重生成同时报告：严格关系 F1、恢复 TP、原 TP 损失、文档下降率、实际输入/输出 token、调用数、端到端均值与 P95。模型版本、硬件、批处理和超时规则统一；相同 token 上限不直接称为相同实际计算量。

风险部分可先使用已有开发网格与冻结测试输出：比较不同风险选择/校准条件的 TP 保留和错误新增，不要求风险模块必须提高 F1。若增加新阈值，应先在开发侧决定，不根据测试成绩挑最优点。

表4-9中，主配置端到端均值为32.17/44.89秒，I0为18.26/25.56秒；可见质量提升有实际延迟代价，追加对象评分又占了大部分额外耗时。因此比继续堆更复杂搜索更有价值的问题，是“同等实际资源下怎样取得更好的质量与保留率”。

H-4已有大候选池求解时限扫描，故不建议重复扫描。只有当正文要宣称“大池局部路由也有稳定的抽取质量收益”时，才需补大池条件下的完整质量评价；当前全部主测试池小于2500，不能由小池主结果外推大池质量。

## 四、不必新训练、但应补到正文的内容

### 1. 换上与正式方法一致的案例

## 五、统计与补实验的停止规则

1. **先冻结本轮问题、比较、种子数和分析口径，再运行。** 不使用“做到 p<0.05 就停”。
2. **保留原3种子及原14项比较族的完整报告。** 不通过删除不利比较、减少校正项，把原来的未显著结果变成显著。
3. 新实验可有事先写明的补充比较族，但须与原研究分开说明；基于已经看过结果而设计的补充分析不能倒写成最初预注册内容。原结果与新增种子的合并估计可报告为扩展分析。
4. 增加种子主要改善训练随机性刻画，不能增加 CDCP 长源金标的独立样本量。8条四源以上金标不会因为3个种子变成24条独立语料证据。
5. 不显著不等于等效。若想主张复杂方法与简单方法效果相当，应事先给出有实际含义的等效/非劣界并配套设计；否则只说当前没有足够证据区分。
6. 本轮不要求每种损失、每种动作、每个数据集都显著。预先规定如何收缩结论，也是合格的实验完成方式。
